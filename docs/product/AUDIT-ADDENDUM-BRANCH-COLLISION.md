## ทำไมเรื่องนี้ยืนยันข้อสรุปของการตรวจรอบก่อน แทนที่จะขัดกับมัน

การตรวจรอบสองบอกว่า **"ตอบให้ได้ก่อนว่าระบบไหนเป็นเจ้าของอะไร ไม่งั้นทุกฟีเจอร์ที่สร้างต่อจากนี้เสี่ยงถูกสร้างซ้ำสองที่"**

ภาคผนวกนี้คือหลักฐานว่าคำเตือนนั้นเกิดขึ้นจริงแล้ว **ภายในสัปดาห์เดียวกัน และเกิดกับตัวรัฐธรรมนูญเอง**
ไม่ใช่กับฟีเจอร์ปลายทาง · และเกิดจากสาเหตุที่ธรรมดาที่สุด: ไม่ได้ดูว่ามีอะไรอยู่แล้วก่อนเริ่ม

## ข้อเสนอ — ไม่ใช่ "เลือกฉบับใดฉบับหนึ่ง" แต่คือ "เอนจินเดียว สองหน้าจอ"

สองฉบับนี้ไม่ได้ขัดกันจริงถ้าแยกให้ถูกว่าใครทำหน้าที่อะไร

| ชั้น | ใครควรเป็นเจ้าของ | เพราะ |
|---|---|---|
| **เอนจิน** (ด่าน · เจตนา · Next Best Action) | `main` — `founderMindset.ts` เดิม | ต่อกับ Genome + prompt อยู่แล้ว และเป็นชั้นที่ agent ต้องเชื่อฟัง |
| **พฤติกรรมของ agent** | บล็อกได้ (ของ `main` ถูกแล้ว) | AI ปฏิเสธที่จะ *ลงมือทำแทน* ไม่ใช่การห้ามเจ้าของ |
| **พฤติกรรมบนหน้าจอ** | เตือน ห้ามปิดปุ่ม (ของ branch นี้ถูกแล้ว) | ระบบไม่มีสิทธิ์ห้ามเจ้าของใช้เงินตัวเอง — คนละเรื่องกับ AI ไม่ยอมทำให้ |

⇒ **ไม่ต้องมีสองไฟล์** · เอนจินของ `main` คงไว้ แล้วให้หน้าจอเรียกเอนจินนั้นแบบ "อ่านผล แต่ไม่ปิดปุ่ม"

ส่วนที่ควรยกจาก branch นี้ไปใส่เอนจินของ `main` (ไม่ใช่ยกทั้งไฟล์):

1. **ตัวแปลง `AppData` → ความพร้อม** — การตรวจรอบก่อนระบุเองว่า
   *"`businessGenome.ts` ไม่ import `AppData` เลย ⇒ `readinessFromGenome()` ไม่เคยได้รับข้อมูลของธุรกิจใครเลย"*
   branch นี้เขียนตัวแปลงนั้นไปแล้ว (อ่าน `finance` · `personas` · `marketInsight` · `funnelSource` · `deals`)
   — เป็นชิ้นส่วนที่ห่วงโซ่ **Constitution → Genome → Decision Engine** ขาดอยู่พอดี
2. **บทเรียนสามข้อที่มีเทสต์บังคับแล้ว** และเป็นบั๊กจริงที่เจอจากการถ่ายหน้าจอหลายสถานะ:
   - ด่านห้ามอ่านข้อมูลที่ผู้ใช้ทั่วไปกรอกเองไม่ได้ (เคยอ่าน `growthEco` ซึ่งเป็นหน้าแอดมิน ⇒ ผ่านไม่ได้ตลอดกาล)
   - ด่านห้ามพาไปหน้าที่ต้องใช้แพ็กเสียเงิน (`PAGE_MIN_PLAN`)
   - ข้อมูลสาธิตที่มากับแอปห้ามนับเป็นหลักฐาน (`DEFAULT_DATA` มีดีลปิดแล้ว 1 ดีล ⇒ ผู้ใช้ใหม่ถูกบอกว่ามีลูกค้าจ่ายเงินแล้ว)
3. **`--states` ของ driver** — ถ่ายหน้าจอสามสถานะธุรกิจในคำสั่งเดียว บั๊กข้อ 2 ทั้งสามข้อโผล่จากเครื่องมือนี้
