**ตรวจได้แค่ว่าโค้ดถูก ไม่มีตัวไหนตรวจว่าโค้ดถูกเรียกใช้**

| `contentLinkContract` | คำสัญญาในโพสต์ ↔ เนื้อหาในบทความปลายทาง |

## 2.4 ด่านเดียวก่อน commit ทุกครั้ง

```
npm run ci   =   lint && build && test:run
```

⚠️ ห้ามพูดว่า *"เทสต์ผ่าน"* ถ้ารันแค่ `vitest`/`typecheck` — **`lint` คือขั้นที่ถูกลืมจน CI แดงติดกัน 54 รอบ 3 วัน**
⚠️ **"push แล้ว" ≠ "อยู่บน production แล้ว"** — ต้องเปิดดูผล GitHub Actions ด้วยตาเองก่อนบอกว่าเสร็จ

## รูปแบบ A — รายงานว่าจริง/เสร็จ **ก่อนไปดูของจริง**

> ⚠️ รูปแบบนี้เกิดบ่อยที่สุด และ**ทุกครั้งหลักฐานอยู่ในมือแล้ว**

| ตัวอย่าง | สิ่งที่เกิด |
|---|---|
| บอกว่า *"ยังไม่ได้ยืนยัน Google Search Console"* ทั้งวัน | ยืนยันไปแล้วตั้งแต่เดือนก่อน |
| รายงาน *"เครื่องคำนวณโผล่พ้นขอบจอแล้ว"* | ยังไม่โผล่ |
| รายงาน *"typecheck สะอาด"* | `tsc --noEmit` ที่รากเป็น no-op — ไม่ได้ตรวจอะไรเลย |
| push โค้ดที่ compile ไม่ผ่านขึ้น main | — |

**กลไกที่เหลือไว้**: `npm run ci` เป็นด่านเดียว · `ciGate.test.ts` อ่าน workflow ตัวจริง ·
กฎ *"push แล้ว ≠ อยู่บน production แล้ว"* · `run-ceo-ai-thailand` เปิดเบราว์เซอร์ดูจริงก่อนรายงาน

## รูปแบบ B — เอา **ตัวเลขที่วัดบั๊กของเราเอง** ไปตั้งเป็นข้อเท็จจริงเรื่องตลาด

| ตัวเลขที่เคยเชื่อ | ของจริง |
|---|---|
| `quickcheck = 0` ⇒ *"ไม่มีใครสนใจ"* | ช่องกรอกอยู่**ใต้ขอบจอทุกเครื่อง** |
| `search = 0` ⇒ *"SEO ไม่ได้ผล"* | เพิ่ง index ได้ 7 วัน |
| `social 32 / direct 45` | **78 จาก 80 ลิงก์ไม่ติด utm** |
| *"คงผู้ชม 89% ⇒ คอนเทนต์ดีจริง"* | คลิปเป็น Shorts ~20 วิ · **4.9 วินาที/วิว** |
| *"หยุดดูเฉลี่ย 38 วินาที"* | timer เดินต่อหลังผู้ใช้สลับแอป |

**กฎที่เหลือไว้**: ก่อนตีความตัวเลขทุกครั้ง ถามก่อนว่า **"เลขนี้วัดตลาด หรือวัดบั๊กของเรา"**
และ **ห้ามอ้างเปอร์เซ็นต์ใดโดยไม่ระบุตัวหาร**

## รูปแบบ C — **เครื่องมือตรวจที่เดินไม่ครบ หรือให้คะแนนกลับด้าน**

## รูปแบบ D — **เขียนถูก ≠ ถูกเรียกใช้**

| ตัวอย่าง | สิ่งที่เกิด |

## รูปแบบ E — **แก้ในแชต ≠ แก้แล้ว**

บทสนทนาหายไปกับ context window **แต่เอกสารอยู่ต่อ** — และรอบถัดไปเราจะอ่านเอกสารนั้นแล้วเชื่อมันอีก

- สถานะ "ด่านปล่อยของ" ถูกเขียนกระจาย **14 ไฟล์** ⇒ วันที่มันเปลี่ยน ไม่มีอะไรบังคับให้ไล่แก้ครบ

**กลไกที่เหลือไว้**: `briefDocsContract` + `releaseGates` **อ่านไฟล์ `.md` ตัวจริง** ·

## รูปแบบ F — **แก้ทิศหนึ่ง แล้วเลยไปอีกทิศ**

# 7 · Part 2 จะตอบอะไร

เจ้าของตั้งโจทย์ไว้: **"คนที่เข้ามาในระบบต้องเกิด aha! แล้วเกิด viral"**

Part 1 (เอกสารนี้) ตอบว่า **ระบบคืออะไร และกฎอะไรกันเราไม่ให้โกหกตัวเอง**
Part 2 จะตอบว่า **aha! ของเราอยู่ตรงไหน วัดยังไง และอะไรทำให้มันถูกส่งต่อ**

โจทย์ที่ Part 2 ต้องแก้ ตั้งอยู่บนข้อเท็จจริงจาก Part 1:

1. **aha! ที่มีอยู่แล้วและพิสูจน์ได้** = ผู้ใช้เห็น **ตัวเลขของตัวเอง** เป็นครั้งแรก
   (เครื่องตรวจสินค้าเร็ว · เครื่องประเมินตลาด · เครื่องคำนวณราคา) — ฟรี ไม่ต้องสมัคร แต่งตัวเลขไม่ได้
2. 🔴 **แต่ aha! ที่ไม่มีใครเห็น = ไม่มี aha!** — 86% ไม่เลื่อนหน้าเลย
   ⇒ งานของ Part 2 ไม่ใช่ "สร้าง aha! ใหม่" แต่คือ **ย้าย aha! ที่มีอยู่ขึ้นมาให้ถึงตา**
3. **viral ต้องมีของให้ส่งต่อ** — และของที่คนส่งต่อได้ ต้องเป็น **ตัวเลขของเขา** ไม่ใช่โฆษณาของเรา
4. 🔴 **และต้องวัดได้ว่ามันเกิดจริง** — ซึ่งวันนี้ยังวัดไม่ได้ เพราะ `utm` ครอบคลุม 2.2%
