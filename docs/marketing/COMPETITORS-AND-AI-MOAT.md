# คู่แข่งในไทย + เราสร้าง AI Model ต่อจาก SaaS ได้ไหม

> ตรวจ 16 ส.ค. 2569 · ทุกรายการค้นเจอจริงและเปิดดูได้ (ลิงก์ท้ายเอกสาร)
> **คำถามที่ตั้ง: "ผมคิดว่าไม่มีคู่แข่งนะ" — ตรวจแล้ว: มีครับ และมีมากกว่าที่คิด**

## 2. แล้วเรายังเหลืออะไรที่คนอื่นไม่มี

ตัดสิ่งที่ทับซ้อนออกหมดแล้ว เหลือ 3 อย่างที่ตรวจแล้วว่าไม่มีใครทำครบ:

| จุดต่าง | ทำไมคนอื่นลอกยาก |
|---|---|
| **เดินจาก "ยังไม่มีธุรกิจ" → "มีระบบพอยื่น ISO" ในที่เดียว** | คนทำเอกสาร ISO ไม่รู้เรื่องหาลูกค้า · คนทำ AI ธุรกิจไม่รู้เรื่อง ISO |
| **ระบบที่ "เถียงกลับ"** — ใส่ตัววัดโดยไม่บอกที่มา ระบบขึ้นเตือนว่าตอบผู้ตรวจไม่ได้ | ต้องมีคนที่ตรวจ ISO จริงมา 20+ ปีถึงจะรู้ว่าผู้ตรวจถามอะไร |
| **ประสบการณ์ตรวจจริงของ B.TC ฝังในกฎของระบบ** | ซื้อไม่ได้ · จ้างไม่ได้ · ต้องใช้เวลาสะสม |

> **แต่ทั้ง 3 ข้อนี้ไม่มีค่าเลย ถ้าลูกค้าแยกไม่ออกว่าเราต่างจาก ChatGPT ยังไง** → ข้อ 3

## 3. ⚠️ คู่แข่งตัวจริงคือ ChatGPT / Gemini — และคุณพูดถูก

> *"กลุ่มนี้ยังแยกไม่ออกระหว่างระบบเรากับ ChatGPT/Gemini หรือ AI อื่น ๆ"*

**นี่คือความเสี่ยงอันดับ 1 ของธุรกิจนี้** ไม่ใช่ FUJIFILM ไม่ใช่ AIS

เพราะลูกค้าจะคิดว่า *"ก็ถาม ChatGPT เอาก็ได้ ฟรีด้วย"* แล้วเราต้องอธิบายว่าทำไมต้องจ่าย ฿590–5,900/เดือน

### สิ่งที่ ChatGPT ทำไม่ได้ "โดยโครงสร้าง" ไม่ใช่แค่ทำได้แย่กว่า

| | ChatGPT / Gemini | ระบบเรา |
|---|---|---|
| ถามอะไรก็ตอบ | ✅ ตอบทุกอย่าง ลื่นไหล | ตอบแคบกว่า เฉพาะเรื่องธุรกิจ |
| **บอกว่าคุณยังขาดอะไร** | ❌ ไม่รู้ว่าคุณทำอะไรไปแล้ว | ✅ รู้ว่าข้อกำหนดข้อไหนยังไม่มีเจ้าของ |
| **เถียงกลับเมื่อคุณทำผิด** | ❌ คุณบอกอะไรมันก็เชื่อ | ✅ *"ตัววัดนี้ตอบผู้ตรวจไม่ได้"* — บังคับสายโซ่ |
| **แต่งตัวเลขไหม** | ⚠️ แต่งได้ และแต่งบ่อย | ✅ **แต่งไม่ได้โดยโครงสร้าง** (Insight type ไม่มีชนิด 'fact') |
| **ออกหลักฐานที่ใช้ยื่นตรวจ** | ❌ ได้แค่ข้อความ | ✅ CSV/JSON ผูกกับเลขข้อกำหนด |
| **เก็บสถานะข้ามวัน/ข้ามคน** | ⚠️ จำได้บ้าง แต่ไม่เป็นระบบ | ✅ ทะเบียนที่ทีมใช้ร่วมกันได้ |

**ประโยคเดียวที่ควรใช้บนหน้าเว็บและในคลิป:**

> **ChatGPT ให้ "คำตอบ" · เราให้ "ระบบที่บอกว่าคุณยังขาดอะไร"**
> ถามอย่างเดียวไม่มีวันรู้ว่าลืมอะไร เพราะมันตอบเฉพาะสิ่งที่คุณถาม

⚠️ ตอนนี้หน้าเว็บเรา **ยังไม่มีประโยคนี้อยู่เลย** — นั่นคือช่องว่างที่ต้องปิด

## 4. สร้าง AI Model ต่อจาก SaaS ได้ไหม — ได้ แต่ต้องเข้าใจว่า "โมเดล" หมายถึงอะไร

มี 4 ระดับ ต้นทุนและความเป็นไปได้ต่างกันคนละโลก:

| ระดับ | คืออะไร | ทำได้ไหมตอนนี้ | ต้นทุน |
|---|---|---|---|
| **0. Prompt engineering** | เขียน prompt เก่ง ๆ ให้ Claude | ✅ **ทำอยู่แล้ว** (`cfoPrompt`, `draftPrompt`, `cmoResearchPrompt`) | ฿0 |
| **1. RAG — คลังความรู้ของเรา** | ให้ AI ค้นจากคลัง ISO/skill ของเราก่อนตอบ | ✅ **ทำได้เลย** ข้อมูลมีแล้ว (skill 60+ ตัว · 4 มาตรฐาน) | หลักพัน–หมื่น |
| **2. Fine-tune โมเดลเปิด** | สอนโมเดลเล็กด้วยข้อมูลของเรา | ⚠️ **ทำได้ แต่ยังไม่มีเชื้อเพลิง** — ต้องการตัวอย่างจริงหลักพัน เรามีเกือบ 0 | หลักหมื่น–แสน |
| **3. เทรนโมเดลตั้งต้นเอง** | สร้างโมเดลจากศูนย์ | ❌ **ไม่ควรทำ** ต้นทุนหลักร้อยล้าน+ และไม่ได้เปรียบอะไร | — |

### ระดับที่ควรตั้งเป้า: **1 ตอนนี้ → 2 เมื่อมีข้อมูลพอ**

### 🔑 สินทรัพย์จริงที่จะกลายเป็นโมเดลได้ — และเรากำลังเก็บมันอยู่แล้ว

ข้อมูลที่ทำให้โมเดลมีค่า ไม่ใช่ปริมาณ แต่คือ **ข้อมูลที่ไม่มีในอินเทอร์เน็ต**

ระบบเราออกแบบมาให้ผลิตข้อมูลชนิดนี้พอดี:

```
กระบวนการจริงของ SME ไทย
   → ตัววัดที่เขาเลือกใช้
      → ความเสี่ยง/คุณค่าที่ตัววัดนั้นเฝ้าอยู่   ← ช่อง whyFrom
         → ข้อกำหนด ISO ที่ผูกอยู่
            → ผู้ตรวจรับหรือไม่รับ              ← ผลลัพธ์จริง
```

**ไม่มีชุดข้อมูลแบบนี้ในโลก** — ChatGPT เทรนจากอินเทอร์เน็ต และสายโซ่นี้ไม่เคยถูกเขียนลงอินเทอร์เน็ต
มันอยู่ในหัวที่ปรึกษาและในห้องตรวจเท่านั้น

**นี่คือคูเมืองจริง** ตรงกับบทเรียนข้อ 25 ของ Dark AI Marketing:
*"AI จะกลายเป็นมาตรฐาน สิ่งที่สร้างความแตกต่างคือข้อมูล"*

### ⚠️ แต่ประตูยังไม่เปิด — บอกตรง ๆ

| ต้องมี | มีจริงตอนนี้ |
|---|---|
| ทะเบียนกระบวนการจากธุรกิจจริง ~1,000 ชุด | **1 workspace** |
| ตัววัดที่มี whyFrom จากคนจริง | ~0 |
| ผลว่าผู้ตรวจรับ/ไม่รับ | 0 |

**เส้นทางมี เชื้อเพลิงยังไม่มี** — และเชื้อเพลิงมาจากผู้ใช้ ไม่ได้มาจากการเขียนโค้ด ML

### สิ่งที่ควรทำตอนนี้เพื่อให้ระดับ 2 เป็นไปได้ในอนาคต

1. ✅ เก็บข้อมูลให้ถูกโครงตั้งแต่วันแรก — **ทำแล้ว** (`quickcheck_submissions`, `processRegister`)
2. ⬜ เพิ่มสัญญาณ "คำตอบนี้ใช้ได้จริงไหม" (👍/👎) ทุกที่ที่ AI ตอบ → กลายเป็น label สำหรับ fine-tune
3. ⬜ บันทึกผลตรวจจริง (ผู้ตรวจรับ/ไม่รับข้อไหน) เมื่อมีลูกค้าเดินถึงขั้นนั้น
4. ⬜ ทำ RAG จากคลัง skill ที่มีอยู่ (ระดับ 1) — ได้ผลเร็วและถูกที่สุด

## 5. สรุปเป็นข้อ ๆ

1. **มีคู่แข่ง** — ISO document SaaS ไทย 6–7 เจ้า · AI-for-SME มี **AIS × Microsoft** เข้ามาแล้ว
2. **แต่ไม่มีใครทำครบเส้นทาง** "เริ่มธุรกิจ → โต → วางระบบ → ยื่น ISO" ในภาษาไทย
3. **คู่แข่งตัวจริงคือ ChatGPT** และเรายังไม่ได้อธิบายความต่างบนหน้าเว็บเลย ← ต้องแก้ก่อนอย่างอื่น
4. **AI model ทำได้** — ควรไประดับ RAG ก่อน · fine-tune รอข้อมูลจริง · ห้ามเทรนเอง
5. **คูเมืองคือสายโซ่ กระบวนการ→ตัววัด→ความเสี่ยง→ข้อกำหนด→ผลตรวจ** ที่ไม่มีในอินเทอร์เน็ต
6. ⏳ **นาฬิกาเดินแล้ว** — AIS ตั้งเป้า 700 SME ภายในสิ้นปี 2569 เราอยู่ที่ผู้ใช้จ่ายเงิน 0 ราย
