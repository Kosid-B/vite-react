## 3. เลนส์ Market Validation — เราข้าม Gate ไปแล้ว

Skill กำหนดลำดับไว้: `Problem Hypotheses → Market Sizing → MVP Feasibility → Pre-Sale Test`
แล้วค่อย Build

**สิ่งที่เกิดขึ้นจริง: Build ครบ 30+ หน้าก่อน แล้วยังไม่เคยทำ Pre-Sale Test**

### Kill Switch — ต้องรายงานตามกติกาของ skill

Skill เขียนไว้ว่า *"หากไม่มี Pain Point ที่ชัดเจน ต้องรายงานความเสี่ยงและเสนอ Pivot ทันที"*

รายงานตามตรง: **เรายังไม่มีหลักฐานว่า Pain Point นี้รุนแรงพอให้คนจ่าย** — และ
**เราก็ยังไม่มีหลักฐานว่ามันไม่รุนแรงพอเช่นกัน** เพราะไม่เคยถาม

นี่ยังไม่ใช่จุดที่ต้อง Pivot ผลิตภัณฑ์ แต่เป็นจุดที่ **ต้องหยุดสร้างฟีเจอร์ แล้วย้อนกลับไปทำ
ขั้นตอนที่ข้ามไป** — Pivot ที่ต้องทำคือ pivot ของ *การใช้เวลา* ไม่ใช่ของ *ตัวสินค้า*

### หลักฐานสนับสนุน: Pre-Sale Test ทำได้อยู่แล้วแต่ไม่ได้ใช้

Skill ระบุว่าระบบเรามีเครื่องมือ Pre-Sale Test ในตัว — เปิดหน้าร้าน `/b/<slug>` →
วัดจากแผง "🧪 พิสูจน์ไอเดีย" (เป้า 10 คนที่ทิ้งช่องทางติดต่อจริง)

**หน้าร้านในระบบตอนนี้ = 0 ร้าน** เครื่องมือพิสูจน์ไอเดียที่เราสร้างเอง เรายังไม่เคยใช้กับตัวเอง

## 4. หลักฐานใหม่ชิ้นที่ 1 — Google ไม่รู้จักเราเลย

```
ผู้เข้าชม 60 คน แยกตามที่มา:
  direct (พิมพ์เอง/บุ๊กมาร์ก)  30
  social (เฟซบุ๊ก/ติ๊กต็อก)    28
  other                          2
  search (Google)                0   ← ไม่มีเลยแม้แต่คนเดียว
```

ทั้งที่เรามี **23 URL ใน sitemap + บทความ 10 ชิ้น** ที่ prerender ไว้แล้ว

สาเหตุที่น่าจะเป็น — ตรวจในโค้ดแล้ว:

- ❌ **ไม่มี `google-site-verification` ในเว็บทั้งเว็บ** (grep ทั้ง `index.html` = 0 ผลลัพธ์)
  → Google Search Console **ไม่เคยถูกยืนยัน** → sitemap ไม่เคยถูกส่ง
- ✅ `robots.txt` ถูกต้อง เปิดให้ crawler ทุกตัวรวม AI (GPTBot/PerplexityBot/ClaudeBot)
- ✅ sitemap.xml สร้างอัตโนมัติตอน build เรียบร้อย

ตรงกับรายการค้างใน `CLAUDE.md` ที่เขียนไว้ตั้งแต่ทำ Marketplace SEO เสร็จ:
*"งานคนหลัง merge: ส่ง sitemap.xml เข้า Google Search Console"* — **ยังไม่ได้ทำ**

> เราลงแรงสร้าง server-side SEO เต็มรูปแบบ (HTMLRewriter, JSON-LD, canonical, prerender)
> แล้วไม่ได้กดปุ่มสุดท้ายที่ใช้เวลา 10 นาที · **นี่คืองานที่คุ้มค่าที่สุดในเอกสารทั้งฉบับ**

⚠️ ยืนยันจากเครื่องนี้ไม่ได้ว่าเว็บถูก index หรือยัง (สภาพแวดล้อมนี้ออกเน็ตไปหาเว็บจริงไม่ได้)
ต้องเช็คเองด้วยการค้น `site:ceoaithailand.org` ใน Google

## 5. หลักฐานใหม่ชิ้นที่ 2 — Marketplace SEO ยังทำไม่ได้ (ตาม skill เอง)

Skill `marketplace-seo` มีข้อ **Recovery** เขียนไว้ตรงเคสนี้พอดี:

> *"Very few listings: Focus on content-driven SEO (blog and guides) until listing volume
> supports strong category pages."*

สถานะ supply จริง: **หน้าร้าน 0 · skill วางขาย 0 · RFQ 0 · ออเดอร์ 0**

แปลว่า:

| สิ่งที่ skill แนะนำ | ทำได้ไหมตอนนี้ | เพราะ |
|---|---|---|
| Category page optimization (`/b`) | ⛔ ไม่ได้ | หน้า category ว่างเปล่า — เข้าข่าย "thin page" ที่ skill เตือนเอง |
| Listing page + Product/LocalBusiness schema | ⛔ ไม่ได้ | ไม่มี listing ให้ render |
| ItemList schema, breadcrumb, internal linking | ⛔ ไม่ได้ | ไม่มีของให้เชื่อม |
| **Content-driven SEO (บทความ/ไกด์)** | ✅ **ทำได้ทันที** | มีบทความ 10 ชิ้นแล้ว |

**กลไก marketplace SEO ที่สร้างไว้ไม่ได้พัง — มันแค่ไม่มีของให้แสดง**
เป็นโครงสร้างพื้นฐานที่รออุปทาน ไม่ใช่ปัญหาที่ต้องแก้ตอนนี้

⚠️ ถ้าปล่อยให้ Google เข้ามาเจอ `/b` ที่ว่างเปล่าตอนนี้ อาจเสียมากกว่าได้
(anti-pattern ข้อ "Thin category pages" ของ skill เอง)
→ **ถ้ายังไม่มีหน้าร้าน ควรพิจารณา `noindex` ที่ `/b` ไว้ก่อน** แล้วค่อยเปิดเมื่อมีร้านจริง ≥ 5 ร้าน

## 7. แผน 3 สัปดาห์ — เรียงตาม "ได้คำตอบต่อชั่วโมงที่ลงแรง"

### สัปดาห์ที่ 1 — เปิดประตู (งานเทคนิค ~2 ชม.)

- [ ] ยืนยัน Google Search Console + ส่ง `sitemap.xml` · เช็ค `site:ceoaithailand.org`
- [ ] ใส่ `google-site-verification` ใน `index.html` (หรือยืนยันผ่าน DNS TXT ใน Cloudflare)
- [ ] พิจารณา `noindex` ที่ `/b` จนกว่าจะมีหน้าร้าน ≥ 5 ร้าน
- [ ] ติด `?seg=` ในลิงก์ทุกอันที่ลงคอนเทนต์ (ดู skill `seg-message-match`)
- [ ] เลิกอ่าน `skill_purchases.price` เป็นรายได้ — กรอง `pay_method='admin-free'` ออกทุกที่

### สัปดาห์ที่ 2 — ถามคน (งานที่ให้คำตอบมากที่สุด)

- [ ] โทรหาผู้สมัคร 2 คน (24 & 28 ก.ค.) ถาม 3 คำถาม:
      *ตอนสมัครคิดว่าจะได้อะไร · เปิดมาแล้วเจออะไร · ทำไมไม่ได้ใช้ต่อ*
- [ ] หาเจ้าของธุรกิจที่ใช่ 5 คนคุยตรง (กำลังทำ ISO / โตแล้วคุมไม่อยู่)
      ถาม *ตอนนี้แก้ปัญหานี้ยังไง จ่ายเท่าไหร่* — **ห้ามเอาระบบให้ดูใน 20 นาทีแรก**
- [ ] ใช้ skill `pain-gain-discovery` ร่างชุดคำถาม

### สัปดาห์ที่ 3 — ทดสอบว่ามีคนจ่ายไหม

- [ ] เปิดหน้าร้านของเราเองที่ `/b/<slug>` = Pre-Sale Test ที่ skill บอกให้ทำ
      (แก้ปัญหาข้อ 5 ไปพร้อมกัน — marketplace มีของชิ้นแรก)
- [ ] เขียนบทความ 2 ชิ้นที่ตอบคำถามที่ **ได้ยินจากการสัมภาษณ์จริง** ไม่ใช่ที่เราเดา
      (content-driven SEO ตาม Recovery clause)

## 9. สิ่งที่ **ไม่ควร** ทำในช่วงนี้

- ❌ **สร้างฟีเจอร์เพิ่ม** — มี 30+ หน้า ผู้ใช้จริง 0 คน · ฟีเจอร์ที่ 31 ไม่ได้แก้ปัญหานี้
  (รวมถึงหน้า `process` ที่เพิ่งทำเสร็จ — มันมีค่าตอนมีคนใช้ ไม่ใช่ก่อนหน้านั้น)
- ❌ **เขียนข้อความ Hero ใหม่** — ยังไม่มีหลักฐานว่ามันพัง (ดู `landingFunnel.funnelCaveats`)
- ❌ **ทำ Hyper-Personalization / Dynamic Persona** — ไม่มีพฤติกรรมของใครให้ personalize
- ❌ **ยิงแอด** — ส่งคนแปลกหน้าเข้ากรวยที่ยังไม่รู้ว่ารั่วตรงไหน = จ่ายเงินซื้อสัญญาณรบกวน
- ❌ **ไล่ยอดวิว** — คลิป 500 วิวจากเจ้าของโรงงาน มีค่ากว่า 14,500 วิวจากคนทั่วไป

## 10. บทเรียนที่ต้องจำ (ข้อ 25 ของหนังสือ ในเวอร์ชันของเรา)

> *"AI ไม่ใช่ความได้เปรียบอีกต่อไป สิ่งที่สร้างความแตกต่างคือข้อมูล คุณภาพของกลยุทธ์
> และความเข้าใจลูกค้า"*

เรามี **AI ครบ** · มี **โครงสร้างข้อมูลครบ** (first-party, PDPA-safe, A/B, funnel)
สิ่งที่ขาดคือชิ้นที่สาม — **ความเข้าใจลูกค้า** ซึ่งซื้อไม่ได้ สร้างด้วยโค้ดไม่ได้
และเป็นชิ้นเดียวที่ต้องได้มาจากการคุยกับคนจริง

**เราสร้างเครื่องมือวัดที่ดีกว่าที่คนส่วนใหญ่มี แล้วยังไม่มีอะไรให้วัด — นั่นคือทั้งหมดของปัญหา**
