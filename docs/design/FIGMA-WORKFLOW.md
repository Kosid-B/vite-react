## ⚠️ Figma ไม่ใช่ตัวตัดสินขอบจอ

ไฟล์จัดวางตามค่าใน CSS จริง แต่เบราว์เซอร์คิดความสูงบรรทัดต่างจาก Figma
(ในกรอบ 390 พาดหัวเครื่องคำนวณจบที่ ~458px · **ในเบราว์เซอร์จริง 572px**)

⇒ **"ผ่านใน Figma" ยังไม่พอ** — ต้องวัดซ้ำในเบราว์เซอร์ทุกครั้งหลังเขียนโค้ด
ใช้ `mobileFoldContract.test.ts` + ฮาร์เนส Playwright ที่บังคับ worst case (`?seg=food` + `ceo_ai_ab='ab-B'`)

## ขั้นตอนทำงาน

1. เจ้าของแก้ดีไซน์ในไฟล์ (กรอบไหนก็ได้)
2. บอกผู้ช่วยว่า "แก้ Figma แล้ว"
3. ผู้ช่วยอ่านดีไซน์ผ่าน `get_design_context` (ต้องโหลด skill `figma-design-to-code` ก่อน)
4. เขียนเป็นโค้ดจริง → **วัดซ้ำทั้ง 3 ขนาดในเบราว์เซอร์ + ส่งภาพหน้าจอยืนยัน**
5. เทสต์ต้องผ่านก่อน push

## skill ของ Figma ที่ต้องโหลดก่อนเรียกเครื่องมือ (บังคับ)

| เครื่องมือ | ต้องโหลดก่อน |
|---|---|
| `use_figma` | `figma-use` |
| `create_new_file` | `figma-create-new-file` |
| `get_design_context` | `figma-design-to-code` |
| สร้างหน้า/วิวทั้งหน้า | `figma-generate-design` (คู่กับ `figma-use`) |

⚠️ ฟอนต์ Kanit ใน Figma ใช้สไตล์ชื่อ **`SemiBold` / `ExtraBold` (ไม่มีเว้นวรรค)** — ต่างจาก Inter ที่เป็น `Semi Bold`
ต้อง `listAvailableFontsAsync()` ตรวจก่อนเสมอ ห้ามเดาชื่อสไตล์
