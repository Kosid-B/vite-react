## สิ่งที่อยู่ในไฟล์

**กรอบเครื่อง 3 ขนาด** — ขนาดมาจากการวัดจริงด้วย Playwright ไม่ใช่สเปกเครื่อง

| กรอบ | จอ | เห็นได้จริง | เส้นแดงอยู่ที่ | ชั้น CSS ที่ใช้ | พาดหัวเครื่องคำนวณจบที่ (ใน Figma) |
|---|---|---|---|---|---|
| iPhone SE | 320×568 | 482 | 482 | `≤768` + `≤389` + `≤340` | **425** (เหลือ 57px) |
| iPhone 8 | 375×667 | 581 | 581 | `≤768` + `≤389` | **423** (เหลือ 158px) |
| iPhone 13 | 390×664 | 578 | 578 | `≤768` | **514** (เหลือ 64px) |

- **แถบแดงล่างเส้น = พื้นที่ที่แถบคุกกี้บัง** (`position:fixed` สูง 86px) — ล็อกไว้ ห้ามวางของสำคัญ
- ทั้ง 3 กรอบใส่ดีไซน์ปัจจุบันครบแล้ว (21 ส.ค. 2569) — แต่ละกรอบใช้ค่าตามชั้น media query ของความกว้างนั้นจริง
  (nav · hero · พาดหัวเครื่องคำนวณ) ⇒ เทียบข้ามกรอบได้ว่าการบีบแต่ละชั้นคืนพื้นที่มาเท่าไร

**สิ่งที่กรอบเหล่านี้ *ไม่* ได้จำลอง** (จดไว้กันเข้าใจผิด — ไม่ใช่ของที่ลืม)
- ใต้พาดหัวเครื่องคำนวณลงไป (ฟอร์ม 5 ช่อง + ผลลัพธ์) ไม่ได้วาด — จอแรกจบก่อนถึงตรงนั้น
- `subLead` ในย่อหน้ารองที่จริงเป็นตัวหนาสีขาวบรรทัดแรก · ในกรอบรวมเป็นสีเดียว
- glow เรเดียลหลัง hero · แถบ `.lp-promo-strip` (ซ่อนบนมือถืออยู่แล้ว)

⚠️ **`· ระยะห่าง Npx` = margin จริงของ CSS** — Figma auto-layout ไม่มี margin รายชิ้น จึงใส่เป็นเฟรมใส
ห้ามลบ ไม่งั้นความสูงรวมจะต่ำกว่าของจริง (ตอนแรกกรอบ 390 ไม่มี ⇒ เตี้ยกว่าความจริง 56px)

### แก้กรอบ 390 ที่เคยวางผิด (21 ส.ค. 2569)
เจอตอนไล่ค่า CSS เพื่อสร้างอีก 2 กรอบ — ทั้ง 3 ข้อกระทบ "ตกขอบจอหรือไม่" โดยตรง:

| ที่ผิด | เดิม | จริง |
|---|---|---|
| margin ระหว่างชิ้นใน hero + ใต้พาดหัว | ไม่มีเลย | badge 8 · h1 8 · ย่อหน้ารอง 10 · ใต้ปุ่ม 8 · h2 6 · ป้าย 12 |
| padding ซ้ายขวาของการ์ดเครื่องคำนวณ | 0 (ข้อความกว้าง 342) | **24** (ข้อความกว้างจริง 294 ⇒ ตกบรรทัดมากกว่า) |
| line-height ข้อความใต้พาดหัว | 160% | **170%** |

⇒ พาดหัวเครื่องคำนวณในกรอบ 390 ขยับจาก 458 → **514px**

**Variables `CEO AI · สี`** — 9 โทเคน 2 โหมด (`เข้ม` / `สว่าง`)
ชื่อตรงกับโทเคนในโค้ด (`bg` `bg3` `border` `white` `slate4` `slate5` `cyan4` `cyan5` `amber5`)
ค่ามาจาก `DARK_C` / `LIGHT_C` ใน `src/pages/LandingPage.tsx` ⇒ แก้สีใน Figma แล้วแปลงกลับเป็นโค้ดได้ตรงตัว

## ⚠️ Figma ไม่ใช่ตัวตัดสินขอบจอ

ไฟล์จัดวางตามค่าใน CSS จริง แต่เบราว์เซอร์คิดความสูงบรรทัดต่างจาก Figma
🟢 วัดจริง 20 ส.ค. 2569 (เบราว์เซอร์ · worst case): กรอบ 390 พาดหัวเครื่องคำนวณจบที่ **572px**
🟢 วัดจริง 21 ส.ค. 2569 (Figma หลังใส่ margin+padding ที่ขาด): **514px** ⇒ ยังต่างกัน ~58px
(ก่อนแก้ต่างกัน 114px — การใส่ margin/padding ที่ขาดปิดช่องว่างไปได้ครึ่งหนึ่ง ไม่ใช่ทั้งหมด)

⇒ **"ผ่านใน Figma" ยังไม่พอ** — ต้องวัดซ้ำในเบราว์เซอร์ทุกครั้งหลังเขียนโค้ด
ใช้ `mobileFoldContract.test.ts` + ฮาร์เนส Playwright ที่บังคับ worst case (`?seg=food` + `ceo_ai_ab='ab-B'`)

## ขั้นตอนทำงาน

1. เจ้าของแก้ดีไซน์ในไฟล์ (กรอบไหนก็ได้)
2. บอกผู้ช่วยว่า "แก้ Figma แล้ว"
3. ผู้ช่วยอ่านดีไซน์ผ่าน `get_design_context` (ต้องโหลด skill `figma-design-to-code` ก่อน)
4. เขียนเป็นโค้ดจริง → **วัดซ้ำทั้ง 3 ขนาดในเบราว์เซอร์ + ส่งภาพหน้าจอยืนยัน**
5. เทสต์ต้องผ่านก่อน push
