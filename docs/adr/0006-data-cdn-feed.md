# ADR-0006 — CDN ข้อมูล: feed รวมที่แคชที่ขอบ ให้ Marketing OS ดึงไปวิเคราะห์

- **สถานะ**: `proposed` — ไม่มีด่านกั้นแล้ว (22 พ.ย. 2569) แต่ **ยังไม่ได้สร้าง** (ดู §อัปเดตสถานะ)
- **วันที่**: 20 พ.ย. 2569 · **ที่มา**: เจ้าของสั่ง "ทำ CDN ข้อมูล"

## บริบท

ADR-0002 ทำให้ OS **เห็นเหตุการณ์** (push ทีละ event) แต่สิ่งที่ OS ต้องใช้วิเคราะห์
และออกแบบสื่อโฆษณาคือ **ภาพรวม** (อัตราจบเครื่องคำนวณ · สัดส่วน seg · อัตราเลื่อนถึง CTA)
ซึ่งเป็นค่า aggregate ของเรา ไม่ใช่ event เดี่ยว ⇒ ต้องมีขา **pull** คู่กับขา push

ท่าที่ถูกต้องทางสถาปัตยกรรมคือ `GET /api/os-feed` บน Worker (Cloudflare)
คืน JSON รวมที่ไม่มี PII + `Cache-Control: public, max-age=…` ⇒ แคชที่ขอบ
⇒ OS ดึงบ่อยแค่ไหนก็ไม่ลงไปถึง Supabase (= "CDN ข้อมูล")

## 🔴 ทำไมยังทำไม่ได้ (ตรวจแล้ว ไม่ใช่เดา)

ตรวจจาก `supabase/migrations/0051_landing_funnel.sql` ตัวจริง:

```sql
revoke all on function public.landing_funnel_agg(int) from public;
grant execute on function public.landing_funnel_agg(int) to authenticated;
```

⇒ ฟังก์ชันรวมข้อมูลที่มีอยู่ **anon เรียกไม่ได้** (และตัวตารางก็ปิด RLS + revoke grant)
⇒ feed สาธารณะต้องมี **rpc ใหม่ที่ anon เรียกได้** = migration = **แตะ schema**
⇒ ตอนเขียน ติด `schemaChangeAllowed()` ซึ่งกั้นอยู่ (เหตุผลเดิม: Phase 1 Acceptance #2 — ดู §อัปเดตสถานะ)

ทางเลี่ยงที่ไม่แตะ schema มีทางเดียว: ให้ Worker ถือ **service-role key** แล้วอ่านตรง
— 🔴 **ไม่เอา**: Worker เสิร์ฟหน้าเว็บสาธารณะ · บั๊กเส้นทางเดียวบนนั้นเท่ากับยกสิทธิ์
เขียนทั้งฐานข้อมูลให้คนนอก · และ GOTCHA `run_worker_first` พิสูจน์แล้วว่าเส้นทางบน Worker
พลาดได้โดยไม่มีอาการให้สังเกต

## การตัดสินใจ

**หยุดไว้ที่นี่โดยเจตนา** และบันทึกไว้ว่าหยุดเพราะอะไร · สิ่งที่ต้องเกิดก่อนเดินต่อ มี 1 อย่าง:
เจ้าของยืนยันว่า **Phase 1 Acceptance #2 ผ่าน** (เกณฑ์ผ่านของมันไม่มีเขียนไว้ที่ไหนในรีโปนี้
⇒ ผู้ช่วยรู้ได้ทางเดียวคือเจ้าของบอก)

### 🔁 อัปเดตสถานะ — 21 พ.ย. 2569 (ไม่ลบของเดิม · ของเดิมคือบริบทที่ตัดสินใจตอนนั้น)

🟢 เจ้าของอนุมัติ **Phase 1 Acceptance #2** แล้ว ⇒ เงื่อนไขที่ ADR นี้เขียนไว้ **เกิดขึ้นจริงแล้ว**
🔴 **แต่ ADR นี้ยัง `blocked`** — เพราะตอนเขียน เรามองห่วงโซ่ไม่ครบ: `GATE_CHAIN` มี **3 ขั้น**
และขั้นที่ 3 **`Freeze Phase 1 baseline`** ยังไม่ปิด ⇒ `schemaChangeAllowed().allowed` ยังเป็น `false`

⚠️ **นี่คือความผิดของ ADR ฉบับนี้เอง ไม่ใช่ของเจ้าของ** — เขียนว่า "ต้องเกิด 1 อย่าง" ทั้งที่
`releaseGates.ts` ระบุ 3 ขั้นมาตั้งแต่ต้น ⇒ บทเรียน: **อ้างด่านต้องอ้างทั้งห่วงโซ่ ห้ามอ้างขั้นเดียว**

⇒ สิ่งที่ต้องเกิดต่อไปคือ **freeze baseline ของ Phase 1 จริง ๆ** · งานที่เหลือ
(rpc `os_feed_agg()` · `/api/os-feed` · cache · ป้ายจำนวนตัวอย่าง) ยังเป็นรายการเดิมทุกข้อ

### 🔁 อัปเดตสถานะ — 22 พ.ย. 2569 (ไม่ลบของเดิม)

🟢 **ด่านที่ 3 ปิดแล้ว** — เจ้าของสั่งว่า *"นิยาม freeze baseline แก้ไขได้ เพื่อให้ใช้งานได้"*
⇒ นิยามถูกเขียนเป็นเกณฑ์ที่ตรวจจากรีโปได้ (`src/lib/phase1Baseline.ts`) และเส้นตั้งต้นถูกวัดจริง
   แล้วล็อกด้วยเทสต์ ⇒ `schemaChangeAllowed().allowed = true`
⇒ ADR นี้จึง **ไม่ `blocked` อีกต่อไป** แต่ยัง **ไม่ `accepted`** เพราะ *ยังไม่มีใครสร้างมัน* —
   สถานะจึงเป็น `proposed` · ⚠️ **"ไม่มีด่านกั้น" ไม่เท่ากับ "ทำแล้ว"**

⚠️ สิ่งที่ยังจริงเหมือนเดิมทุกข้อ: ขา pull ยังไม่มี ⇒ **ห้ามบอกว่า "เชื่อมสองระบบครบแล้ว"**

เมื่อปลดแล้ว งานที่เหลือเล็ก และระบุได้ครบตอนนี้:
1. rpc ใหม่ `os_feed_agg()` — คืน **ค่ารวมเท่านั้น** · ไม่มีแถวรายคน · ไม่มี PII · `anon` เรียกได้
2. เส้นทาง `/api/os-feed` ใน `src/server.ts` + เพิ่มใน `workerRouting.test.ts`
3. `Cache-Control: public, max-age=900, stale-while-revalidate=3600` (15 นาทีพอ — ตัวเลขพวกนี้ขยับช้า)
4. ⚠️ ทุกค่าต้องติดป้ายจำนวนตัวอย่าง · ค่าที่ต่ำกว่า `MIN_FOR_RATE` (100) ต้องคืน `null`
   **ห้ามคืนเลข 0 แทน "ยังไม่พบ"** (ของเราเองผิดข้อนี้มาแล้ว · `zeroIsNotProof`)

## ผลที่ตามมา

- 🔴 ตอนนี้ OS **ยังวิเคราะห์ภาพรวมของเราไม่ได้** — เห็นแต่ event ที่เราส่งให้
  ⇒ ห้ามบอกเจ้าของว่า "เชื่อมสองระบบครบแล้ว" · ครบครึ่งเดียว (push ได้ · pull ยังไม่ได้)
- ✅ ไม่มีโค้ดครึ่ง ๆ ค้างในรีโปที่ไว้ใจไม่ได้

## ทางเลือกที่ไม่เลือก

| ทางเลือก | ทำไมไม่เลือก |
|---|---|
| ให้ Worker ถือ service-role key | ยกสิทธิ์เขียนทั้ง DB ไปอยู่บนเส้นทางสาธารณะ (เหตุผลเต็มด้านบน) |
| ส่ง aggregate เข้า `marketing-track` เป็น event | ฟังก์ชันรับแค่ 10 event ที่กำหนด · และ aggregate ไม่ใช่เหตุการณ์ |
| ไฟล์ JSON ที่ commit ลงรีโป + เสิร์ฟเป็น static | ได้แคชที่ขอบจริง **แต่ข้อมูลนิ่งตามรอบ deploy** และต้องมีคนกดอัปเดต = วงจรปิดด้วยมือ |
| ฝืนทำ migration เลย | ขัดด่านปล่อยของที่เจ้าของตั้งไว้เอง — ด่านที่ข้ามได้เมื่อสะดวก ไม่ใช่ด่าน |
