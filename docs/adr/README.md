# ADR — บันทึกการตัดสินใจทางสถาปัตยกรรม

> **ADR ย่อจาก Architecture Decision Record** — บันทึก "ตัดสินใจอะไร เพราะอะไร แลกอะไรไป"
> ไม่ใช่คู่มือการใช้งาน และไม่ใช่สเปก

## ADR มีไว้แก้ปัญหาอะไรในโปรเจกต์นี้

🔴 ปัญหาจริงที่เกิดซ้ำ ๆ และ ADR แก้ตรงจุด:
**การตัดสินใจอยู่ในแชต แล้วแชตหายไปกับ context window** — รอบถัดไปเราอ่านแต่ผลลัพธ์ (โค้ด)
แล้วเดาเหตุผลใหม่เอง · บางครั้งเดากลับด้านจนรื้อของที่ตั้งใจทำ
(บทเรียนเดียวกับ [LESSONS-LEDGER](../LESSONS-LEDGER.md) #41: *ยอมรับว่าพูดผิดในแชต ≠ แก้แล้ว*)

**เส้นแบ่งกับเอกสารที่มีอยู่แล้ว — ห้ามเขียนซ้ำกัน**

| เอกสาร | ตอบคำถาม | อัปเดตเมื่อ |
|---|---|---|
| `CLAUDE.md` | **กฎที่ต้องทำตามวันนี้** | กฎเปลี่ยน |
| `docs/LESSONS-LEDGER.md` | **เคยพลาดอะไร → กลไกอะไรกันไว้** | พลาด |
| `docs/adr/*` | **ทำไมถึงเลือกทางนี้ และไม่เลือกทางอื่น** | ตัดสินใจครั้งใหม่ (ของเดิมไม่ลบ) |

⚠️ **ADR ไม่ถูกแก้ย้อนหลัง** — ตัดสินใจใหม่ที่ขัดของเก่า ให้เขียน ADR ใหม่แล้ว
ตั้งสถานะของเก่าเป็น `superseded-by` · ประวัติที่ถูกลบคือประวัติที่สอนอะไรไม่ได้

## สถานะที่ใช้ได้ (มีเทสต์บังคับ)

| สถานะ | ความหมาย |
|---|---|
| `accepted` | ตัดสินใจแล้ว และทำแล้ว |
| `proposed` | เสนอแล้ว ยังไม่ตัดสิน |
| `blocked` | ตัดสินใจแล้วว่าจะทำ แต่ **ติดด่านที่ระบุชื่อได้** |
| `rejected` | พิจารณาแล้วไม่ทำ (เหตุผลสำคัญกว่าตัวการตัดสินใจ) |
| `superseded` | ถูกแทนด้วย ADR ใหม่ |
