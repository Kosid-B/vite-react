# ADR-0010 — "Freeze Phase 1 baseline" เป็นเกณฑ์ที่ตรวจจากรีโปได้ ไม่ใช่คำยืนยันในแชต

- **สถานะ**: `accepted`
- **วันที่**: 22 พ.ย. 2569
- **ผู้ตัดสิน**: เจ้าของ (*"นิยาม freeze baseline แก้ไขได้ เพื่อให้ใช้งานได้"*)

## บริบท

`releaseGates.GATE_CHAIN` มี 3 ด่าน และด่านที่ 3 `Freeze Phase 1 baseline` ถูกตั้งไว้เป็น
`verifiable: 'owner-only'` ⇒ **ปิดได้ทางเดียวคือรอเจ้าของพิมพ์ว่า freeze แล้ว**

🔴 ปัญหาที่เห็นชัดแล้วจากด่านก่อนหน้า: `Phase 1 Acceptance #2` ผ่านไปเมื่อ 21 พ.ย. 2569
**โดยที่เกณฑ์ผ่านไม่เคยถูกเขียนลงรีโปเลยสักรอบ** ⇒ สิ่งที่ยืนยันได้มีแค่ *"เจ้าของบอกว่าผ่าน"*
ไม่ใช่ *"ตรวจแล้วว่าผ่าน"* · ถ้าด่านที่ 3 ยังเป็น owner-only มันจะซ้ำรอยเดิมแน่นอน

และระหว่างนั้น ด่านนี้กั้นงานจริงอยู่ 2 ก้อน: ขา pull ของ Marketing OS (ADR-0006) และ
เวลา 6 ตัวที่ `financialTruth` ต้องการ (paid_at · first_login_at · …) — ทั้งคู่ต้องแตะ schema

⚠️ จุดที่ต้องระวัง: ด่านนี้ไม่ได้ตั้งมาเพื่อ "กันไม่ให้ทำอะไร" แต่ตั้งมาเพื่อ **กันการเปลี่ยนแปลง
ที่เทียบผลไม่ได้** — ถ้าไม่มีเส้นตั้งต้น คำถาม *"แก้แล้วดีขึ้นไหม"* ตอบไม่ได้สักครั้ง
(ความผิดเดิมของโปรเจกต์นี้: กระโดดไป Act ตอน Check ยังตาบอด)

## การตัดสินใจ

**นิยาม freeze ใหม่ให้ตรวจได้จากรีโป แล้วเปลี่ยนด่านเป็น `verifiable: 'in-repo'`**

> **freeze = เขียนตัวเลขตั้งต้นลงรีโป พร้อม "วิธีนับ" และ "วันที่" แล้วล็อกด้วยเทสต์**

เงื่อนไขปิดด่าน (`phase1Baseline.baselineIssues()` คืนรายการเปล่า):

1. ตัวชี้วัดที่บังคับทุกตัวต้องเป็น `measured` — ไม่ใช่ `assumed` ไม่ใช่ `unavailable`
2. ทุกตัวต้องมี **วิธีนับที่รันซ้ำได้** (คำสั่ง SQL จริง · "ดูจากแดชบอร์ด" ไม่นับ)
3. ทุกตัวต้องมีวันที่วัด และวันที่ต้องไม่อยู่ในอนาคต
4. ต้องบันทึกขอบเขตของ Phase 1 และ **ของจริงตัวไหนเสิร์ฟตัวเลขชุดนั้นอยู่** (ชื่อ bundle บน production)
5. ตัวที่ค่าเป็น `0` ต้องมีประโยคกำกับว่า **มันไม่ได้แปลว่าอะไร** (`0` = ยังไม่พบ ≠ อัตราจริงเป็นศูนย์)

🔴 **fail-closed**: ตัวที่บังคับแล้ว *วัดไม่ได้* **ไม่ปิดด่าน** ถึงจะบอกเหตุผลครบ —
วัดไม่ได้แปลว่ายังไม่มีเส้นตั้งต้น ไม่ใช่ "ยกเว้นให้"

🔴 **"freeze" ไม่ได้แปลว่าห้ามเปลี่ยนตัวเลขตลอดกาล** — แปลว่า **เปลี่ยนแล้วต้องรู้ตัว**
เทสต์ล็อกค่าทุกตัวไว้ตรง ๆ ⇒ แก้ค่าโดยไม่แก้เทสต์ = แดง (หลักเดียวกับ `BASELINE_DEBT`/`FLUSH_WINDOW_MS`)

เส้นตั้งต้นที่วัดจริงเมื่อ 22 พ.ย. 2569 (production + ฐานของอีกระบบ) ถูกบันทึกครบใน
`src/lib/phase1Baseline.ts` ⇒ ด่านที่ 3 **ปิดแล้ว** ⇒ `schemaChangeAllowed().allowed = true`

## กลไก

| กลไก | กันอะไร |
|---|---|
| `src/lib/phase1Baseline.ts` | แหล่งเดียวของเส้นตั้งต้น + เกณฑ์ปิดด่าน (pure · ไม่เรียก DB) |
| `releaseGates` import สถานะจาก `baselineFrozen()` | สถานะด่านคำนวณ ไม่ใช่พิมพ์มือ ⇒ โกหกไม่ได้ |
| `phase1Baseline.test.ts` ล็อกค่าทีละตัว + `REQUIRED_KEYS` ทั้งชุด | กัน "ลดเกณฑ์เพื่อให้ผ่าน" (ถอด required สักตัวแล้วอ้างว่าครบ) |
| เทสต์ตัวอย่างสังเคราะห์ 6 แบบ (วิธีนับสั้น · วันที่อนาคต · วัดไม่ได้แต่ใส่ 0 …) | พิสูจน์ว่าเกณฑ์แดงจริง ไม่ใช่ผ่านเพราะไม่ได้ตรวจอะไร |
| `releaseGates.test.ts` — ด่าน `in-repo` ห้ามเป็น `unknown` | กัน "ตรวจได้แล้วแต่ยังไม่ตรวจ" |
| ด่านสถานะค้างในเอกสาร (ทั่วไปจาก `GATE_CHAIN` แล้วตั้งแต่ 21 พ.ย.) | ด่านปิดแล้วแต่เอกสารยังบอกว่ายังไม่ผ่าน = แดง |

## ผลที่ตามมา

- 🟢 แตะ schema/migration ได้แล้ว — ADR-0006 (ขา pull) เปลี่ยนจาก `blocked` → `proposed`
  และเวลา 6 ตัวของ `financialTruth` เริ่มทำได้
- 🔴 **แตะได้ ≠ แตะตามใจ** — verdict ยังผูกกับ regression gate ของส่วนที่กระทบ และ
  **เส้นแบ่งความเป็นเจ้าของยังอยู่ครบ** (ห้ามสร้าง migration `marketing_*` — คนละเรื่องกับด่านนี้)
- 🔴 **"ไม่มีด่านกั้น" ≠ "ทำแล้ว"** — ADR-0006 ยังไม่มีใครสร้าง
- ⚠️ ด่านที่ 1–2 ยัง `owner-only` เหมือนเดิม และยังยืนยันได้แค่ "เจ้าของบอกว่าผ่าน" — อดีตข้อนั้นแก้ย้อนหลังไม่ได้
- ⚠️ ตัวเลขตั้งต้นหลายตัวต่ำมาก (จ่ายจริง 0 · quickcheck 1) ⇒ **ห้ามเอาไปคิดเป็นอัตรา** ทุกกรณี

## ทางเลือกที่ไม่เลือก

| ทางเลือก | ทำไมไม่เลือก |
|---|---|
| คงไว้เป็น `owner-only` แล้วรอเจ้าของยืนยัน | ซ้ำรอย Acceptance #2 เป๊ะ ๆ — ปิดด่านโดยไม่มีเกณฑ์ ⇒ รอบหน้าเราจะยืนยันไม่ได้ว่าผ่านเพราะอะไร |
| ให้ freeze = ติด git tag | tag ไม่ได้บอกว่า *ตัวเลขเท่าไร วัดยังไง* ⇒ เป็นพิธีกรรมที่ตอบคำถาม "ดีขึ้นไหม" ไม่ได้ |
| ให้ baseline ดึงตัวเลขสดจาก DB ตอนรันเทสต์ | baseline ที่ขยับเองไม่ใช่ baseline · และผูกเทสต์เข้ากับเครือข่าย/ฐานข้อมูล = เทสต์ที่แดงเพราะเรื่องอื่น |
| ปิดด่านโดยไม่ต้องวัดครบ (ยอมให้ `unavailable` ผ่านได้ถ้าบอกเหตุผล) | เท่ากับแปล `unknown` เป็น `closed` — ความผิดที่ `releaseGates` ตั้งมาเพื่อกันโดยตรง |
