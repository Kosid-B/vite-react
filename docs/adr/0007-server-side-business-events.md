# ADR-0007 — event ฝั่งธุรกิจ 7 ตัวต้องยิงจากเซิร์ฟเวอร์ (ท่า B)

- **สถานะ**: `proposed` — ตัดสินใจแนวทางแล้ว ยังไม่ลงมือ
- **วันที่**: 20 พ.ย. 2569 · **ที่มา**: เจ้าของสั่ง "ลุย A ต่อ B"

## บริบท

`marketing_event_definitions` ของ OS นิยาม event ขั้น `business` ไว้ 7 ตัว:
`trial_started` · `signup_complete` · `subscription_started` · `purchase_completed` ·
`lead_created` · `content_published` · `tracking_error`

`marketing-track` **ปฏิเสธทั้ง 7 ตัวโดยออกแบบ** (รับแต่ 10 event ฝั่งเบราว์เซอร์)
— และนั่น **ถูกต้องแล้ว**: เบราว์เซอร์อ้างว่า "ซื้อสำเร็จ" เองไม่ได้ ใครก็ยิงได้

## การตัดสินใจ (แนวทาง)

ยิงจากจุดที่ **รู้ความจริงอยู่แล้ว** ฝั่งเซิร์ฟเวอร์ ไม่ใช่จากหน้าเว็บ:

| event | จุดที่รู้ความจริง | หมายเหตุ |
|---|---|---|
| `purchase_completed` · `subscription_started` | `verify-slip` (หลัง SlipOK ผ่าน) · `stripe-webhook` | จุดเดียวที่ยืนยันเงินเข้าจริง |
| `trial_started` · `signup_complete` | `App.tsx` ตอนเริ่ม trial / สมัครเสร็จ | 🔴 ต้องย้ายไปฝั่งเซิร์ฟเวอร์ ไม่งั้นปลอมได้ |
| `tracking_error` | `client_errors` (rpc `track_client_error`) | มีข้อมูลอยู่แล้ว ยังไม่ส่งต่อ |
| `lead_created` · `content_published` | ยังไม่มีจุดที่รู้ความจริง | 🔴 **ห้ามเดา** — ต้องมีของจริงก่อน |

ข้อบังคับ 3 ข้อ:
1. ปลายทางต้องรับ event พวกนี้ก่อน — **`marketing-track` ตอนนี้ยังไม่รับ**
   และซอร์สของมัน**ไม่อยู่ในรีโปนี้** ⇒ 🔴 ต้องให้เจ้าของแก้ฝั่งนั้น หรือเปิดฟังก์ชันใหม่ฝั่งเรา
2. ส่งจากเซิร์ฟเวอร์ = ต้องมี secret ⇒ ต้องตัดสินใจว่าใช้คีย์ไหน (ยังไม่ตัดสิน)
3. ใช้ `osCodec` ชุดเดียวกับฝั่งเบราว์เซอร์ ⇒ กฎ PII และการตรวจก่อนส่งต้องไม่มีสองมาตรฐาน

## ผลที่ตามมา

- 🔴 **ยังเริ่มไม่ได้จนกว่าข้อ 1 จะชัด** — เขียนโค้ดส่งไปตอนนี้ = โค้ดที่ยิงแล้วถูกปฏิเสธ 100%
- ⚠️ ถ้าทำแค่ครึ่ง (ส่ง 5 ตัวที่มีจุดรู้ความจริง) OS จะเห็นกรวยที่ขาดกลาง
  ⇒ ดีกว่าไม่มีข้อมูล **แต่ต้องประกาศว่าขาดตัวไหน** ไม่ให้มันคำนวณอัตราจากตัวตั้งที่ไม่ครบ

## ทางเลือกที่ไม่เลือก

| ทางเลือก | ทำไมไม่เลือก |
|---|---|
| ยิง 7 ตัวจากเบราว์เซอร์ | ใครก็ปลอม "ซื้อสำเร็จ" ได้ · และปลายทางปฏิเสธอยู่แล้ว |
| รอให้ครบทั้ง 7 ตัวก่อนเริ่ม | 2 ตัวไม่มีจุดรู้ความจริงเลย = รอตลอดไป |
| เดาจุดยิงของ `lead_created` | ไม่มีของจริงรองรับ ⇒ สร้างตัวเลขที่ดูเหมือนจริง = ผิดกฎสูงสุด |

## กลไก (ตอนลงมือ)

`OS_BUSINESS_EVENTS` ใน `src/lib/marketingOs.ts` ถูกล็อกด้วยเทสต์แล้วว่า
**ห้ามโผล่ในสายเบราว์เซอร์** — ต่อท่า B แล้วเทสต์นั้นต้องยังเขียวอยู่
