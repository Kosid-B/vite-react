# ADR-0003 — แยกชั้นแปลง (codec) ออกจากชั้นส่ง

- **สถานะ**: `accepted` · **วันที่**: 20 พ.ย. 2569 · **ที่มา**: เจ้าของสั่ง "ทำ codec file"

## บริบท

ตอนแรกการแปลง (คัด PII · ตัดความยาว · ประกอบ payload) อยู่ในไฟล์เดียวกับการส่ง
ปัญหาที่เห็นทันทีเมื่อเพิ่มคิวของค้าง (ADR-0005): **payload ที่ค้างในเครื่องผู้ใช้ถูกสร้างด้วย
โค้ดเวอร์ชันก่อน แต่ถูกส่งด้วยโค้ดเวอร์ชันนี้** ⇒ "สิ่งที่เราเขียนลงไป" กับ "สิ่งที่เราอ่านขึ้นมา"
ไม่ใช่เรื่องเดียวกันอีกต่อไป ⇒ ต้องมีขา **decode + ตรวจ** ไม่ใช่มีแต่ขา encode

## การตัดสินใจ

`src/lib/osCodec.ts` ถือการแปลงทั้งสองทาง และ **pure ทั้งไฟล์**
(ไม่มี `fetch` · ไม่มี storage · ไม่อ่าน env · ไม่ import `config`/`supabase`)

- `encodeOsEvent()` ภายใน → สายส่ง · `decodeOsEvent()` สายส่ง → ชนิดที่ตรวจแล้ว
- `wireIssues()` คืน **รายการเหตุผล** ที่ปลายทางจะปฏิเสธ — ใช้ตรวจ**ก่อน**ใช้เน็ตทุกครั้ง
- 🔴 กฎ PII ย้ายมาอยู่ที่นี่ด้วย เพราะ **การกัน PII คือการแปลง ไม่ใช่การส่ง**
  วางไว้ที่ชั้นส่ง = เลี่ยงได้ด้วยการเพิ่มทางส่งใหม่อีกทาง
- การพึ่งพาเป็นทางเดียว: `marketingOs` → `osCodec` (ไม่วน)

## ผลที่ตามมา

- ✅ ทดสอบได้ครบทุกทางโดยไม่ต้องมีเน็ต/เบราว์เซอร์
- ✅ `osPackage` และ `osOutbox` ใช้กฎชุดเดียวกัน ไม่เขียนกฎซ้ำ
- ⚠️ ไฟล์เพิ่มขึ้น 1 ไฟล์ และเทสต์เดิมที่อ่านซอร์สต้องย้ายไปอ่านไฟล์ใหม่

## ทางเลือกที่ไม่เลือก

| ทางเลือก | ทำไมไม่เลือก |
|---|---|
| ปล่อยรวมไว้ในไฟล์ส่ง | ชั้นที่ตรวจ PII จะถูกข้ามได้ทุกครั้งที่เพิ่มทางส่งใหม่ |
| มีแต่ `encode` ไม่มี `decode` | ของที่ค้างในเครื่องจะถูกส่งโดยไม่ตรวจ = เชื่อโค้ดเวอร์ชันก่อนโดยไม่มีเหตุผล |
| ใช้ zod/ตัวตรวจสคีมาจากภายนอก | เพิ่ม dependency ให้บันเดิลหน้าเว็บเพื่อกฎ 6 ข้อ · และ `wireIssues` ต้องคืน**เหตุผลภาษาไทย**ที่อ่านได้ |
