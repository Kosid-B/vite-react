# ADR-0014 — เติมตาราง `marketing_os` ตาม "ของที่แอปใช้" ไม่ใช่ "ของที่มีข้อมูล"

- **สถานะ**: `accepted`
- **วันที่**: 26 พ.ย. 2569
- **ผู้ตัดสิน**: เจ้าของ (*"merge #461 เลย ไปต่อ"* — เลือก **ไปต่อ** แทนข้อเสนอให้หยุด)

## บริบท

การย้ายแอป Marketing OS มาชี้ฐานเรา (ADR-0011 ข้อ ①) ถูกลองทำจริงวันนี้จากเครื่องเจ้าของ
แล้ว **ไม่สำเร็จ** · วัดสดบน production พบว่าของที่ขาดไม่ใช่สิทธิ์ ไม่ใช่ Exposed schemas แต่เป็น **ตาราง**

| วัด 26 พ.ย. 2569 (ก่อนตัดสิน) | ค่า |
|---|---|
| ตารางที่แอป OS query | **17** |
| มีใน `marketing_os` + มีแถว | **5** |
| มีแค่ใน `public` และ 0 แถว (และ `public.marketing_*` ไม่ใช่ของเรา) | **4** |
| 🔴 ไม่มีในฐานเราเลยทั้งสอง schema | **8** |
| ทั้ง 12 ตารางนั้นในฐานเขา (`bjozpwdtqbpwcxnqguka`) | **0 แถวทุกตัว** |

🔴 **ราก: `0066` คัดลอกตาราง "ที่มีข้อมูล" (11 ตัว · 48 แถว) ไม่ได้คัดลอกตาราง "ที่แอปใช้"**
และ CLAUDE.md เอาคำตอบของ *"ย้ายข้อมูลมาครบไหม"* ไปตอบ *"แอปใช้งานได้ไหม"* (ledger #107)

ผู้ช่วยเสนอให้ **หยุดข้อ ①** เพราะตอบ Golden Question ไม่ได้ (ไม่ชี้ไปที่ลูกค้า/หลักฐาน/กำไร/Scale)
และทางเลือกที่เหลือมีความเสี่ยงสูง · **เจ้าของเลือกไปต่อ** ⇒ ADR นี้บันทึกการตัดสินนั้นและขอบเขตของมัน

## การตัดสินใจ

**เติมให้ครบ 17 ตามที่แอป query โดยอ่านโครงสร้างจากฐานเขา ห้ามเดา · แต่ไม่แตะเรื่อง identity**

1. `0070_marketing_os_home_tables` — `marketing_offers` · `marketing_ctas` · `marketing_action_items`
   🔴 **ก้อนนี้ถูก apply ลง production ก่อน โดยเซสชันบนเครื่องเจ้าของ (08:14:17 UTC) และไม่มีไฟล์ในรีโป**
   ⇒ รีโปเก็บไฟล์ย้อนหลังโดยคัดลอก statement จริงจาก `schema_migrations` มาเป๊ะ (ledger #108)
2. `0071_marketing_os_content_tables` — อีก 9 ตัว เรียงตามการอ้างอิง
   `campaigns → hypotheses → content_items → content_versions → ai_jobs → content_assets
   → approval_requests → compliance_findings → tracking_links`
3. **ตัด FK ไป `auth.users` ออกทั้ง 7 เส้น** (`created_by` ×5 · `requested_by` · `reviewed_by` · `resolved_by`)
   คงชนิด `uuid` และ `NOT NULL` ตามเดิม
4. สิทธิ์ตาม ADR-0013 ไม่เปลี่ยน: RLS เปิด · **ไม่มี policy** · revoke `anon`/`authenticated` · grant `service_role`
5. 🔴 **4 ตารางที่เคยมีแค่ใน `public` ถูกสร้างใหม่ใน `marketing_os` ไม่ได้ย้ายของเขา**
   `public.marketing_*` ยังไม่ใช่ของเรา ⇒ ห้ามแตะ แม้จะว่าง

## ผลที่ตามมา

- 🟢 แอป OS จะไม่ล้มที่ `relation does not exist` อีก สำหรับ 17 ตารางที่มันรู้จัก
- 🟢 ย้อนกลับได้เหมือนเดิม: ฐานเขายังครบทุกแถว ไม่ถูกแตะเลย (`drop schema marketing_os cascade`)
- 🔴 **ยังไม่ใช่ "ย้ายเสร็จ"** — ด่าน identity ยังเปิด: `workspace_members` **11 คน** มีใน `auth.users`
  ของเรา **0 คน** ⇒ แอปที่พึ่ง RLS + cookie ล็อกอินยังอ่านไม่ได้ · ทางเดียววันนี้คือ **service key ฝั่งเซิร์ฟเวอร์**
  ซึ่งข้าม RLS ทั้งหมด ⇒ ใครเปิดหน้าไหนก็เห็นทุก workspace ถ้าไม่เขียนการตรวจในโค้ดแอปเอง
- 🔴 **หนี้ที่รับไว้แล้ว**: ฐานไม่การันตีว่า `created_by`/`requested_by`/`reviewed_by`/`resolved_by`
  ชี้ไปที่คนที่มีจริง เพราะ FK ถูกตัด ⇒ ความถูกต้องย้ายไปอยู่ที่โค้ด
- 🟡 **ยังไม่ได้ทดสอบว่าแอปเปิดขึ้นจริง** — เซสชันคลาวด์เปิดโฟลเดอร์แอปไม่ได้ (`not_available`)
  ⇒ เกณฑ์วัด: `marketing_audience_segments` ต้องได้ **6** (ของเขา) ไม่ใช่ **5** (ของเรา)
  + ยืนยันซ้ำด้วยรหัสกลุ่ม `growth`/`employee` ไม่ใช่ `owner`/`sidebiz`
- ⚠️ 12 ตารางใหม่ **ว่างเปล่า** ⇒ หน้าที่แสดงรายการจะว่าง · นั่นถูกต้อง เพราะฝั่งเขาก็ว่าง

## ทางเลือกที่ไม่เลือก

| ทางเลือก | ทำไมไม่เลือก |
|---|---|
| **หยุดข้อ ① (ข้อเสนอของผู้ช่วย)** | ตอบ Golden Question ไม่ได้ · ความเสี่ยงของทางที่เหลือสูง · **แต่เจ้าของตัดสินให้ไปต่อ** ⇒ ข้อเสนอถูกยกเลิกโดยการตัดสิน ไม่ใช่โดยการพิสูจน์ว่าผิด |
| ย้ายตาราง 4 ตัวจาก `public` มาเลย (ของมันว่างอยู่แล้ว) | 🔴 `public.marketing_*` ยังไม่ใช่ของเรา · ว่างวันนี้ไม่ได้แปลว่าว่างพรุ่งนี้ · เส้นแบ่งความเป็นเจ้าของสำคัญกว่าความสะดวก |
| คัดลอกทั้ง 33 ตารางที่เหลือมาให้หมดในทีเดียว | สร้างของที่ไม่มีใครอ่าน = เพิ่มจำนวนตาราง ไม่ใช่เพิ่ม moat · และเดาโครงสร้างยกชุดคือสิ่งที่ ADR-0011 ห้ามไว้ |
| เปิด grant ให้ `authenticated` เพื่อให้แอปอ่านได้เลย | ซ้ำกับที่ ADR-0013 ปัดตกแล้ว — policy ที่อิง `auth.uid()` แมตช์ศูนย์แถวสำหรับผู้ใช้ของเขา แต่เปิดให้ลูกค้าเราอ่านได้ทันที |
| ตัดสิน identity ไปด้วยเลยในรอบนี้ | เป็นการตัดสินที่กระทบ auth/plan/billing ของผลิตภัณฑ์เรา ⇒ ต้องเป็นก้อนของตัวเอง ไม่ใช่ผลพลอยได้ของ migration |
