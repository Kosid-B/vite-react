# Seg Message-Match (Dynamic Landing)

## When to Use This Skill

ใช้สกิลนี้เมื่อ:
- กำลังจะ **โพสต์คอนเทนต์/แคปชัน** แล้วต้องแนบลิงก์ไปหน้า Landing (`/start`)
- วาง **แผน sprint การตลาด** (organic หรือ ยิงแอด) และต้องการให้หน้าที่คนคลิกเข้ามา "ตรงกับสิ่งที่โฆษณา"
- มีคำถามว่า **"จะรู้ได้ยังไงว่าคนที่เข้ามาเป็นกลุ่มไหน"**
- อยากวัดว่า **มุมคอนเทนต์ไหน (กลุ่มไหน) เวิร์ก**

**อย่าใช้** สกิลนี้กับการเขียนตัวแคปชันเอง (ใช้ playbook/`ai-dark-marketing`) — สกิลนี้คุมเฉพาะ "การติดป้าย seg + จับคู่ให้ถูก"

---

## Core Principle

**`seg` = ป้ายบอกว่า "โพสต์นี้ยิงกลุ่มไหน" — ไม่ใช่ "คนนี้คือใคร"**

คุณไม่ต้องรู้จักตัวบุคคล คุณคุมที่ "ตอนโพสต์" → คนจะ **คัดกลุ่มตัวเอง (self-selection)** ด้วยการคลิกแคปชันที่โดนใจเขา แล้วหน้า Landing จะโชว์ hero + ปุ่ม + ปลายทางให้ตรงกับกลุ่มนั้นทันที

---

## 3 กลุ่ม (seg) + hero + ปลายทาง

| `seg` | ใครคือกลุ่มนี้ | hero ที่เขาเห็น | พาไป |
|-------|----------------|-----------------|------|
| `seller` | มีของขายอยู่แล้ว / อยากเปิดร้าน | "ขายของอยู่แล้ว แต่ลูกค้าหาไม่เจอ?" | เปิดหน้าร้าน (storefront) |
| `newbie` | มือใหม่ ยังไม่เริ่ม กลัวเจ๊ง | "อยากมีธุรกิจ แต่กลัวลงเงินแล้วเจ๊ง?" | ทดสอบไอเดีย (bmc) |
| `owner` | มีธุรกิจแล้ว ทำคนเดียว/อยากมีระบบ | "ทำธุรกิจคนเดียวจนไม่มีเวลาโต?" | ทีม AI (aicompany) |
| _(ไม่ใส่)_ | ไม่รู้กลุ่ม / มาเอง | copy กลาง | ให้เลือกเอง (GoalChooser) |

> ที่มาโค้ด: `src/lib/heroVariant.ts` (`segmentFor` / `pickHeroVariant`) — เป็น source of truth เดียว ถ้าจะเพิ่ม/แก้กลุ่ม แก้ที่ไฟล์นี้ + เทสต์

---

## วิธีทำ (3 ขั้น)

### ขั้น 1 — ระบุกลุ่มของ "โพสต์" (ไม่ใช่ของคน)
ดูว่าแคปชัน/มุมที่จะโพสต์ พูดกับใคร:
- พูดเรื่อง **กลัวเจ๊ง / ยังไม่เริ่ม / เล่าไอเดีย** → `newbie`
- พูดเรื่อง **ทำร้านคนเดียวไม่โต / วางระบบ / SOP-KPI / เจ้าของ** → `owner`
- โพสต์ใน **กลุ่มร้านค้าออนไลน์ / พ่อค้าแม่ค้า / คนมีของขาย** → `seller`
- สรุป/ทั่วไป ไม่เจาะกลุ่ม → **ไม่ต้องใส่** (ปล่อย default)

### ขั้น 2 — ต่อ `&seg=` ท้ายลิงก์ UTM
ฐานลิงก์: `ceoaithailand.org/start?utm_source=<ช่อง>&utm_medium=<organic|paid>&utm_campaign=<ชื่อแคมเปญ>`

ต่อท้ายด้วยกลุ่มที่เลือกในขั้น 1:
```
...&seg=seller
...&seg=newbie
...&seg=owner
```
ตัวอย่าง: `ceoaithailand.org/start?utm_source=fb_group&utm_medium=organic&utm_campaign=sprint_ส.ค.&seg=newbie`

**TikTok/IG:** ใส่ลิงก์ใน bio (แคปชันกดลิงก์ไม่ได้) → เขียน "ลิงก์ในโปรไฟล์"

### ขั้น 3 — วัด แล้วเทน้ำหนักไปมุมที่เวิร์ก
เปิด **Admin → Leads & UTM tab** → ดูว่า `seg` ไหน (+ `utm_source` ไหน) ส่ง lead จริงเยอะสุด → สัปดาห์ถัดไปทำมุม/ช่องนั้นเพิ่ม
- Analytics events ที่เกี่ยวข้อง: `landing_hero_variant` (seg ที่โชว์), `landing_cta_click` (seg + cta), `landing_goal_routed` (พาไปหน้าไหน)

## Auto-fallback (ถ้าไม่ใส่ seg / คนมาเอง)

ระบบเดากลุ่มจาก signal ที่มีจริง ตามลำดับ: `?seg=` → `?goal=` → `utm_*` keyword → referrer

- มาจาก **TikTok / IG** → `newbie` (วัยเริ่ม)
- มาจาก **LinkedIn** → `owner` (B2B/เจ้าของ)
- อื่น ๆ → `default` (copy กลาง)

→ แปลว่าถ้าลืมใส่ ก็ยังพอ personalize ได้ แต่ **ใส่เองแม่นกว่า** เพราะตรงกับแคปชันที่คุณคุม

## Mapping ตัวอย่าง (7-day sprint)

| แคปชัน (มุม) | seg |
|--------------|-----|
| กลัวเจ๊ง / ก๋วยเตี๋ยว | `newbie` |
| ทำร้านคนเดียวไม่โต | `owner` |
| 3 คำถามก่อนลงเงิน | `newbie` |
| เจ้าของที่มีระบบ | `owner` |
| พิมพ์ไอเดีย 1 บรรทัด | `newbie` |
| โพสต์ในกลุ่มพ่อค้าแม่ค้า | `seller` |
| สรุปสัปดาห์ (ทั่วไป) | _(ไม่ใส่)_ |

## กติกา / จริยธรรม (ห้ามข้าม)

- **Message match เท่านั้น** — seg ต้องตรงกับแคปชันจริง อย่าเอา hero กลุ่มหนึ่งไปล่อคนอีกกลุ่ม (โฆษณาไม่ตรงปก = bounce สูง + เสียความเชื่อใจ)
- **ไม่มี fake scarcity** — ทุก hero พูดฟีเจอร์ที่มีจริง (validate / storefront / ทีม AI)
- **ความเป็นส่วนตัว** — ใช้แค่ UTM/referrer ไม่ track ข้ามเว็บ ไม่เก็บ PII (สอดคล้อง Pulse opt-in + PDPA)

---

## Anti-Patterns

- ❌ พยายาม "รู้ว่าคนนี้คือใคร" รายบุคคล — ผิดหลัก · seg ผูกกับโพสต์ ไม่ใช่คน
- ❌ ใส่ seg เดียวกับทุกโพสต์ — เสียประโยชน์ personalization + วัดแยกกลุ่มไม่ได้
- ❌ ใส่ seg ที่ไม่ตรงแคปชัน (เช่นแคปชันมือใหม่ แต่ `&seg=owner`) — message mismatch
- ❌ ลืมดู Leads & UTM — ยิงมั่วไม่รู้ว่ามุมไหนเวิร์ก

## Recovery

- **ลืมใส่ seg:** ไม่พัง — auto-fallback เดาจาก referrer ให้ · โพสต์ครั้งหน้าค่อยใส่
- **อยากได้กลุ่มใหม่ (นอกจาก 3):** แก้ `HERO_VARIANTS` + `segmentFor` ใน `src/lib/heroVariant.ts` แล้วเพิ่มเทสต์ใน `src/lib/__tests__/heroVariant.test.ts`
- **hero ไม่เปลี่ยนตาม seg:** เช็คว่า deploy production แล้ว (Cloudflare) + ลองล้าง query ซ้ำ `?seg=owner` ตรง ๆ · ดู event `landing_hero_variant` ว่า seg ตรงไหม
