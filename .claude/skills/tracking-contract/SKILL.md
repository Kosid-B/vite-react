# สัญญาระหว่างโค้ดกับเครื่องมือวัดผล

> **เกิดจากความผิดพลาดจริง 22 ส.ค. 2569** ระหว่างตั้งค่า GA4 ให้ CEO AI Thailand
> ผู้ช่วยบอกให้เจ้าของ **ลบ `paid_growth` / `paid_scale` / `paid_starter` ทิ้ง**
> โดยอ้างว่า "ไม่มีในโค้ดเลย" — ทั้งที่มันคือ **เหตุการณ์รายได้** ที่ยิงจาก `Billing.tsx`
> สาเหตุ: โค้ดเขียนว่า `track('paid_' + sub.plan, …)` ⇒ grep หาชื่อเต็มไม่มีวันเจอ
> ถ้าเจ้าของทำตาม จะเสียการวัดรายได้รายแพ็กไปถาวร

---

## หลักการเดียวที่ต้องจำ

> **เครื่องมือวัดผลไม่ได้อ่านซอร์สโค้ดของคุณ มันอ่านเฉพาะ "สิ่งที่ถูกส่งออกไปจริงบนสาย"**

ทุกความผิดพลาดในสกิลนี้มาจากการสับสนระหว่าง 3 ชั้นนี้:

```
① สิ่งที่โค้ดเขียน   →   ② สิ่งที่ถูกส่งออกไปจริง   →   ③ สิ่งที่เครื่องมือถูกตั้งค่าให้รับ
   track('paid_'+plan)      event: "paid_growth"          key event: "paid_growth"
   { source: 'x' }          param: "ev_source"            dimension: "ev_source"
```

**ชั้น ② คือความจริงเพียงหนึ่งเดียว** — ①ไม่ใช่ ③ก็ไม่ใช่

---

## 7 กับดัก (ทุกข้อเคยเกิดจริง)

### ① ชื่อถูกเปลี่ยนระหว่างทาง
`analytics.ts` มีชั้น remap: พารามิเตอร์ที่ชนกับระบบ attribution ของ GA4
(`source` `medium` `campaign` `term` `content` …) ถูกเติม `ev_` นำหน้าก่อนส่ง
⇒ โค้ดเขียน `source` แต่ต้องลงทะเบียนใน GA4 ว่า **`ev_source`**
**ตรวจยังไง:** อ่านฟังก์ชัน `track()`/wrapper ให้จบก่อนเสมอ ห้ามอ่านแค่จุดที่เรียก

### ② ชื่อประกอบจากตัวแปร — `grep` ชื่อเต็มมองไม่เห็น
```js
track('paid_' + sub.plan, …)      // → paid_starter | paid_growth | paid_scale
track(r.capped ? 'a' : 'b', …)    // → สองชื่อจากบรรทัดเดียว
```
**ตรวจยังไง:** grep หา `track(` ที่**ตามด้วยอะไรก็ตามที่ไม่ใช่ `'`**
`grep -rnE "track\(\s*[^'\"]"` แล้วไล่อ่านทีละจุด

### ③ ปลายทางสะกดผิด — ของจริงเลยไม่เคยถูกนับ
พบ key event ชื่อ `anding_cta_click` (ตก `l`) ในขณะที่โค้ดยิง `landing_cta_click`
จาก **10 จุด** ⇒ CTA หลักของทั้งเว็บไม่เคยเข้ารายงาน Conversion เลย
**ตรวจยังไง:** เทียบรายชื่อสองฝั่งด้วยเครื่อง ไม่ใช่ด้วยตา — ชื่อที่ต่างกัน 1 ตัวอักษรตาคนจับไม่ได้

### ④ "ตั้งไว้แต่ไม่ได้ต่อ" — ตัวเลข 0 ที่แปลว่าอะไรไม่ได้เลย
Amplitude ได้ 0 event มาหลายเดือนโดยไม่มีใครรู้ (คีย์ไม่ถูกส่งเข้า build step)
key event หลายตัวถูกตั้งไว้ตามแผนที่ยังไม่ได้เขียนโค้ด ⇒ รายงานขึ้น 0 ตลอด
แล้วถูกอ่านว่า "ไม่มีใครทำอะไรเลย"
**กติกา:** `0` มีสองความหมาย — *ไม่มีใครทำ* กับ *เราวัดไม่ได้* · **ห้ามอ่านว่าอย่างแรกจนกว่าจะพิสูจน์ว่าท่อทำงาน**
**วิธีพิสูจน์ท่อ:** ยิงข้อมูลทดสอบเข้าไปจริงแล้วดูว่ามันโผล่ไหม (ใน SQL ใช้ transaction แล้ว rollback)

### ⑤ เก็บแล้วแต่อ่านไม่ได้ ถ้าไม่ลงทะเบียน
GA4: พารามิเตอร์ที่ไม่ได้สร้างเป็น custom dimension จะขึ้น `(not set)` ทั้งที่ข้อมูลถูกส่งครบ
CRM: field ที่ยังไม่สร้าง property จะถูกทิ้งเงียบ ๆ ตอน sync
**กติกา:** "ส่งได้" ≠ "อ่านได้" — เป็นคนละงานกัน ต้องทำทั้งคู่

### ⑥ ไม่ย้อนหลัง — ทุกวันที่ช้าคือข้อมูลที่หายถาวร
custom dimension · key event · data retention ล้วนนับจากวินาทีที่กดบันทึกเท่านั้น
**กติกา:** งานตั้งค่าที่ "ไม่ย้อนหลัง" ต้องขึ้นก่อนงานที่ย้อนหลังได้เสมอ ต่อให้สำคัญน้อยกว่า

### ⑦ ตัวเลขจากคนละแหล่ง เทียบกันตรง ๆ ไม่ได้
GA4 ถูก gate ด้วย consent (ปิดจนกว่าจะกด "ยอมรับทั้งหมด") ⇒ **ต่ำกว่าความจริงเสมอ**
ส่วนตาราง first-party ของเราเองนับทุกคน ⇒ สูงกว่าเสมอ
**กติกา:** ต่างกันคือเรื่องปกติโดยการออกแบบ · ห้ามสรุปว่าฝั่งใดฝั่งหนึ่งพัง

## ขั้นตอนตรวจก่อนแตะการตั้งค่าใด ๆ

1. **อ่าน wrapper ให้จบ** — มี remap / prefix / ตัดทิ้ง / เปลี่ยนชนิดไหม
2. **ทำรายการชื่อจากโค้ด** — รวมชื่อที่ประกอบจากตัวแปรด้วย (กับดัก ②)
3. **ทำรายการชื่อจากเครื่องมือ** — export หรือ screenshot ให้ครบ
4. **เทียบสองรายการด้วยเครื่อง** — หา ①มีในโค้ดแต่ไม่มีในเครื่องมือ ②มีในเครื่องมือแต่ไม่มีในโค้ด
5. **ก่อนลบอะไรก็ตามในฝั่งเครื่องมือ** — ถามให้ครบ 3 ข้อ:
   - มันเคยมีข้อมูลเข้าไหม (ดูจากเครื่องมือ ไม่ใช่จากโค้ด)
   - ชื่ออาจถูกประกอบจากตัวแปรไหม
   - ชื่ออาจถูก remap มาไหม

🔴 **ถ้าตอบไม่ได้ครบ 3 ข้อ = ห้ามลบ** — การลบ config การวัดผลไม่มี undo และข้อมูลที่หายไม่กลับมา

## อย่าเดาหน้าจอของเครื่องมือ

ระหว่างงานเดียวกันนี้ ผู้ช่วยเดา UI ของ GA4 ผิด **3 ครั้ง** (บอกให้หาปุ่มที่ไม่มีอยู่ ·
บอกวิธีลบผิด · บอกว่ากดปุ่มแล้วจะเห็นรายการแต่มันเปิดฟอร์ม) — เกือบทำให้เจ้าของ
สร้าง event ปลอมที่ยิงทุก page view

**กติกา:**
- เครื่องมือมักเขียนวิธีไว้ในหน้าจอเอง (GA4 เขียนว่า *"ให้เลือกดาวข้างชื่อเหตุการณ์"* ในแถบสีฟ้า) — **อ่านสิ่งที่อยู่ตรงหน้าก่อนแนะนำ**
- ถ้าไม่เห็นหน้าจอ ให้**ขอภาพ** อย่าอธิบายเส้นทางจากความจำ
- ปุ่มที่ชื่อคล้ายกันอาจทำคนละเรื่องกันคนละโลก
  (`สร้างเหตุการณ์` = สร้าง event ปลอมขึ้นใหม่ · `เหตุการณ์สำคัญ` = ติดดาวให้ของที่มีอยู่)

## สำหรับงาน CRM โดยเฉพาะ

หลักการเดียวกัน แต่ชื่อของแต่ละชั้นเปลี่ยนไป:

| ชั้น | Analytics | CRM |
|---|---|---|
| ① โค้ด | `track(name, params)` | payload ที่ส่งเข้า API/webhook |
| ② สาย | event + parameter | object + property (ชื่อ internal ไม่ใช่ label ที่เห็นบนจอ) |
| ③ ปลายทาง | custom dimension / key event | property definition · pipeline stage · required field |

**กับดักเพิ่มเฉพาะ CRM:**
- **ชื่อที่เห็นบนจอ ≠ ชื่อที่ API ใช้** — CRM แสดง label ภาษาคน แต่รับ internal name (เช่น `ceo_ai_plan`)
  ⇒ ตั้งค่า mapping ด้วย internal name เสมอ
- **property ที่ยังไม่สร้าง = ข้อมูลถูกทิ้งเงียบ** ไม่มี error ไม่มี log
  ⇒ ต้องสร้าง property ก่อน sync ครั้งแรก ไม่ใช่หลัง
- **คีย์รวมข้อมูล (dedupe key)** — อีเมล/เบอร์ที่พิมพ์ต่างกันนิดเดียวสร้าง contact ซ้ำ
  ⇒ ตกลงคีย์เดียวและ normalize ก่อนส่ง (ตัวพิมพ์เล็ก · ตัดช่องว่าง)
- **ทิศทางการ sync** — เขียนทับกันได้ทั้งสองทาง
  ⇒ ต้องระบุว่าฝั่งไหนเป็นเจ้าของ field ไหน ไม่งั้นข้อมูลจะเด้งไปมา
- **pipeline stage ที่ไม่มีใน CRM** — ดีลจะตกลง stage แรกเงียบ ๆ ไม่ error

## สิ่งที่ต้องเหลือไว้หลังทำงานเสร็จ (ไม่ใช่แค่ตั้งค่าเสร็จ)

1. **รายการชื่อในรีโป** — ไฟล์ที่บอกว่าโค้ดยิงอะไรบ้าง รวมชื่อที่ประกอบจากตัวแปร
2. **เทสต์ที่เทียบสองฝั่ง** — ชื่อในไฟล์ตั้งค่าต้องมีอยู่จริงในโค้ด
3. **บันทึกว่าอะไร "ไม่ย้อนหลัง"** — เพื่อให้คนถัดไปรู้ว่าเลื่อนงานไหนไม่ได้
4. **หลักฐานว่าท่อทำงาน** — วันเวลาที่พิสูจน์ครั้งล่าสุด ไม่ใช่แค่ "ตั้งค่าแล้ว"
