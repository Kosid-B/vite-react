# ตัวอักษรที่มองไม่เห็น

> **เกิดจริง 2 รอบ** — เจ้าของแจ้งเองทั้งสองครั้ง
> **รอบแรก 21 ส.ค. 2569**: ตัวอักษรขาวกลืนพื้นขาวในธีมสว่าง → แก้ 12 คลาส → สร้าง `contrast-audit`
> **รอบสอง 22 ส.ค. 2569**: **กลับมาอีกที่หน้าอื่น** ทั้งที่เครื่องมือรายงานว่าเขียว
> ต้นเหตุรอบสอง: **เครื่องมือเดินไม่ครบทุกหน้า** — เดินแค่ปุ่มที่ *มองเห็น* ใน sidebar
> แต่เมนูส่วนใหญ่อยู่ในกลุ่มที่ยุบไว้ + โหมดโฟกัสซ่อนไว้
> ⇒ หน้าที่มีปัญหาจริง **ไม่เคยถูกสแกนเลยสักครั้ง** แล้วเราอ่านผลเขียวว่า "ไม่มีปัญหา"

---

## หลักการเดียว

> **สีตัวอักษรไม่มีความหมาย จนกว่าจะรู้ว่า "พื้นหลังจริงตอนรัน" คือสีอะไร**

พื้นหลังจริงมักไม่ได้อยู่ใน element เดียวกัน — มันมาจาก element แม่ที่อาจอยู่คนละไฟล์
และเปลี่ยนตามธีม ⇒ **อ่านไฟล์ CSS ตรวจเรื่องนี้ไม่ได้ ต้องวัดในเบราว์เซอร์เท่านั้น**

---

## 3 กลไกที่ทำให้ตัวอักษรหาย (เจอจริงทั้งสาม)

### ① เขียนสีตัวอักษรตายตัว แต่พื้นหลังเปลี่ยนตามธีม
```css
.de-hero-title { color: #fff; }                    /* ถูกในธีมเข้ม */
.de-hero { background: linear-gradient(...); }     /* พลิกเป็นสีอ่อนในธีมสว่าง */
```
⇒ ขาวบนอ่อน = **มองไม่เห็นเลย**
**กติกา:** ถ้าเขียนสีตัวอักษรตายตัว **ต้องเขียนพื้นหลังตายตัวคู่กันใน selector เดียวกัน**
ไม่งั้นให้ใช้โทเคนธีมทั้งคู่

### ② ตัวแปร CSS ที่ไม่เคยถูกประกาศ
`var(--ink1)` ถูกใช้ 154 จุดโดยไม่เคยประกาศที่ไหนเลย
⇒ CSS ถือว่า *invalid at computed-value time* ⇒ ตัวอักษร **สืบทอดสีจากแม่** (มักเป็นสีพื้น)
**กติกา:** ทุก `var(--x)` ต้องมี fallback หรือมีการประกาศจริง — และต้องมีเทสต์ยืนยัน

### ③ `<style>` ในคอมโพเนนต์ทับ `index.css`
`<style>` ที่ฝังใน `.tsx` อยู่ **หลัง** `index.css` ใน DOM ⇒ specificity เท่ากันตัวหลังชนะ
⇒ แก้ `index.css` แล้ว "ไม่ขยับ" โดยไม่มีใครรู้ว่าทำไม
**กติกา:** เช็คด้วย `getComputedStyle` ในเบราว์เซอร์จริง ไม่ใช่อ่านไฟล์
(อ่านไฟล์ = เห็นสิ่งที่เราเขียน · `getComputedStyle` = เห็นสิ่งที่เบราว์เซอร์ใช้จริง)

## 🔴 บทเรียนที่แพงที่สุด: เครื่องมือที่เดินไม่ครบ

เครื่องมือตรวจที่ครอบคลุมไม่ครบ **อันตรายกว่าไม่มีเครื่องมือเลย**
เพราะมันรายงานเขียว แล้วเราหยุดหา — ปัญหาที่เหลือกลายเป็น "ของที่พิสูจน์แล้วว่าไม่มี"

**สิ่งที่ซ่อนหน้าไว้จากตัวตรวจ (ต้องเปิดให้หมดก่อนสแกน):**

| สิ่งที่ซ่อน | ต้องทำก่อนสแกน |
|---|---|
| กลุ่มเมนูที่ยุบอยู่ | กด toggle ทุกกลุ่ม (วนหลายรอบ — กางกลุ่มหนึ่งอาจเผยอีกกลุ่ม) |
| โหมดโฟกัส/onboarding ที่ซ่อนเมนู | ปิดโหมด (`focus-unlock`) ก่อน |
| หน้าที่ล็อกตามแพ็ก | สแกนด้วยบัญชีที่เห็นทุกหน้า |
| เนื้อหาใต้ขอบจอ | `scrollTo(0, scrollHeight)` ทุกหน้า |
| หน้าสาธารณะที่ไม่อยู่ใน sidebar | ใส่ path ตรง ๆ (`/start`, `/calc`, `/b/...`) |
| ธีมที่ไม่ได้เปิดอยู่ | วนสแกน **ทุกธีม** ไม่ใช่ธีมเดียว |
| สถานะที่เกิดเฉพาะบางเงื่อนไข | โหมด guest · ยังไม่มีข้อมูล · error state |

**กติกาบังคับ:** ตัวตรวจต้อง **พิมพ์จำนวนหน้าที่เดินจริง** ออกมาเสมอ
ถ้าตัวเลขนั้นน้อยกว่าจำนวนหน้าที่มีจริง = ผลลัพธ์อ่านไม่ได้ ไม่ว่าจะเขียวแค่ไหน

## เกณฑ์ที่ใช้ตัดสิน

| อัตราส่วน | ความหมาย | ทำยังไง |
|---|---|---|
| **< 2.0** | มองไม่เห็นเลย | 🔴 แก้ทันที · บล็อกการ deploy ได้ |
| **2.0–3.0** | อ่านออกแบบฝืน ๆ | 🟠 แก้ |
| **3.0–4.5** | ผ่านเฉพาะตัวอักษรใหญ่ (≥18.66px หนา หรือ ≥24px) | 🟡 ตรวจขนาดก่อนปล่อยผ่าน |
| **≥ 4.5** | ผ่าน WCAG AA | 🟢 |

⚠️ **ตัวอักษรบนปุ่มสีเข้มก็ตกเกณฑ์ได้** — ขาวบนไซแอน `#06b6d4` = 2.43 ทั้งที่ดูโอเค
ปุ่มหลักของเว็บควรใช้พื้นเข้มกว่านั้น หรือตัวอักษรเข้มแทน

---

## ขั้นตอนที่ต้องทำทุกครั้งที่แตะเรื่องสี

1. **เขียนด้วยโทเคนธีม** ไม่ใช่สีตายตัว (`var(--ink)` `var(--ink3)` `var(--accent-text)`)
2. ถ้าจำเป็นต้องตายตัว → **เขียนพื้นหลังตายตัวคู่กันใน selector เดียวกัน**
3. **รันตัวตรวจในเบราว์เซอร์จริง** ทุกหน้า ทุกธีม เลื่อนจนสุด
4. **อ่านจำนวนหน้าที่เดินจริง** ก่อนอ่านผล — ไม่ครบ = ผลไม่นับ
5. **ดูภาพหน้าจอจริงประกอบ** — ตัวเลขผ่านเกณฑ์ที่นิยามผิด ก็ยังผิดอยู่ดี

## สิ่งที่ต้องเหลือไว้ (ไม่ใช่แค่แก้สีเสร็จ)

1. **ตัวตรวจที่เดินครบ** พร้อมบรรทัดบอกจำนวนหน้าที่เดิน
2. **เทสต์ที่ห้ามสีตายตัวกลับมา** ในคลาสที่เคยพัง
3. **บันทึกว่าหน้าไหนตัวตรวจเข้าไม่ถึง** — จุดบอดที่ประกาศไว้ ดีกว่าจุดบอดที่ไม่มีใครรู้
