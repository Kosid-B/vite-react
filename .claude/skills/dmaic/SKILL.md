# DMAIC — จบที่ข้อเสนอ ไม่ใช่จบที่ปัญหา

> **สั่งโดยเจ้าของโปรเจกต์ 24 ส.ค. 2569**
> *"คุณหมกมุ่นแต่ปัญหา ๆ คุณต้องหาวิธีพัฒนาแล้วประเมินผล แล้วหาทางเลือกที่ดีที่สุดเลย
> ผมอายุ 50 ปีแล้ว อย่าให้ผมเสียเวลาเยอะ"*

## 🔴 ความผิดที่ skill นี้มีไว้กัน

**ไม่ใช่ "วิเคราะห์ผิด" แต่คือ "หยุดอยู่ที่ Analyze"**

รายงานว่าอะไรพัง · ทำไมพัง · เจอบั๊กกี่ตัว · มีจุดบอดอะไรบ้าง — แล้วส่งให้เจ้าของตัดสินใจเอง
= **โยนงานที่หนักที่สุด (การเลือก) กลับไปให้คนที่มีเวลาน้อยที่สุด**

การรายงานปัญหาให้ครบถ้วนดูเหมือนความรอบคอบ แต่ถ้าไม่มีข้อเสนอ มันคือการผลักภาระ
และยิ่งรายการปัญหายาว ยิ่งดูเหมือนทำงานเยอะ ทั้งที่ยัง **ไม่ได้ตัดสินใจอะไรเลยสักข้อ**

| ❌ สิ่งที่เคยส่งมอบ | ✅ สิ่งที่ต้องส่งมอบ |
|---|---|
| "เจอ 13 จุดที่ contrast ไม่ผ่าน" | "แก้ 13 จุดแล้ว · ทางที่เลือกคือ X เพราะ Y · ทาง Z ตกเพราะรู้ผลช้ากว่า" |
| "ตรวจไม่ได้เพราะ proxy บล็อก" | "ตรวจไม่ได้เพราะ proxy บล็อก ⇒ 3 ทางที่ทำได้: A/B/C · แนะนำ A" |
| "มีความเสี่ยง 5 ข้อ" | "ความเสี่ยงที่ต้องตัดสินใจตอนนี้มี 1 ข้อ · อีก 4 ข้อรอได้ถึงเมื่อ..." |

⚠️ **ข้อยกเว้นเดียว**: กฎสูงสุดของโปรเจกต์ (ความถูกต้องมาก่อน) ยังอยู่เหนือ skill นี้ —
ถ้าตรวจไม่ได้ ยังต้องบอกว่าตรวจไม่ได้ **แต่ต้องบอกต่อว่าแล้วจะทำยังไง** ไม่ใช่หยุดแค่นั้น

## 5 เฟส — แต่ละเฟสส่งมอบ "ของ" ไม่ใช่ "การกระทำ"

| เฟส | ของที่ต้องมีอยู่จริงเมื่อจบเฟส | ด่านที่จับได้ |
|---|---|---|
| **D**efine | ปัญหา 1 ประโยค + เป้าหมายเป็น **ตัวเลข** + เส้นตาย | `"ให้ดีขึ้น"` ไม่ใช่เป้าหมาย เพราะวัดไม่ได้ว่าถึงหรือยัง |
| **M**easure | ค่าตั้งต้นที่วัดมาจริง **หรือ** ประกาศว่าวัดไม่ได้เพราะอะไร | ไม่มีค่าตั้งต้น = พิสูจน์ไม่ได้ว่าดีขึ้น ⇒ **งานแรกคือซ่อมการวัด ไม่ใช่แก้ตัวสินค้า** |
| **A**nalyze | สาเหตุราก 1 ข้อที่อธิบายตัวเลขได้ | หลายสาเหตุ = ยังไม่ได้วิเคราะห์ · ข้ามไปแก้ก่อนรู้ว่าแก้อะไร = เดา |
| **I**mprove | **ทางเลือก ≥ 3 ทาง (รวม "ไม่ทำอะไรเลย") + คะแนน + ข้อที่เลือก** | ← จุดที่เคยพลาดตลอด |
| **C**ontrol | กลไกที่ทำให้ของที่ดีขึ้นแล้วไม่ไหลกลับ (เทสต์/ตัววัด/ด่าน) | ของที่ดีขึ้นแล้วไม่มีอะไรเฝ้า จะกลับมาเหมือนเดิมเสมอ |

**กลไกบังคับ**: `dmaicGate()` ใน `src/lib/dmaic.ts` คืน `stuckAt` = เฟสแรกที่ยังไม่ผ่าน
พร้อม `nextAction` เป็นประโยคที่สั่งได้เลย — ไม่ใช่คำถามกลับไปหาเจ้าของ

## Improve — เฟสที่ถูกข้ามบ่อยที่สุด

### กติกา 3 ข้อ

1. **อย่างน้อย 3 ทาง** — ทางเลือกเดียวไม่ใช่การตัดสินใจ มันคือการรายงาน
2. **ต้องมี "ไม่ทำอะไรเลย" เสมอ** — คู่เทียบที่ซื่อสัตย์ที่สุดและถูกลืมบ่อยที่สุด
   (ตัวเดียวกับที่ `competitorMemory.KNOWN_MARKET` บอกว่าเป็นคู่แข่งที่ชนะบ่อยที่สุด)
   ⇒ **ถ้าชนะ "ไม่ทำอะไรเลย" ไม่ได้ แปลว่าอย่าเพิ่งทำ**
3. **ทางที่ติดกฎโปรเจกต์ต้อง "พักไว้" ไม่ใช่หายไปเงียบ ๆ** — เช่นแตะ schema ตอน Gate B ยังไม่ปิด
   ⇒ ได้คะแนน 0 และตกท้ายแถวเสมอ แต่ยังต้องถูกรายงานว่าถูกพักไว้เพราะอะไร

### เกณฑ์ให้คะแนน (`scoreOption`)

| ปัจจัย | น้ำหนัก | ทำไม |
|---|---|---|
| ผลต่อเป้าหมาย | ×3 | ไม่ใช่ "ดีแค่ไหน" แต่คือ **ขยับตัวเลขที่ตั้งไว้แค่ไหน** |
| **เร็วที่จะรู้ผล** | ×2 | ≤ 14 วัน ⇒ ยังตัดสินใจต่อได้ในเดือนเดียวกัน |
| หลักฐาน | ×2 | `hypothesis → research → observed → validated` (งานวิจัยคนอื่นยังไม่พอ) |
| แรงที่ต้องใช้ | ×2 | แรงน้อย = ดี |
| ถอยกลับได้ | ×1 | ของที่ถอยได้ ลองได้เร็วกว่าเสมอ |

🔴 **ของที่ผลใหญ่แต่ต้องรอ 90 วันถึงจะรู้ = เดิมพัน ไม่ใช่การพัฒนา**
เจ้าของมีเวลาจำกัด ⇒ **ทางที่ตอบได้เร็ว มีค่ามากกว่าทางที่ตอบได้สวย**

## รูปแบบการส่งมอบ (บังคับ)

```
เลือก "<ทางที่แนะนำ>" — <เหตุผลสั้น>
<อันดับสอง> ตกไปเพราะ <เหตุผล>
พักไว้: <ทางที่ติดกฎ> เพราะ <กฎอะไร>
———— (รายละเอียดอยู่ข้างล่าง ให้เปิดดูได้ ไม่ใช่บังคับให้อ่าน)
```

**ขึ้นต้นด้วยข้อเสนอ ไม่ใช่ด้วยที่มา** — ที่มาสำคัญ แต่มันคือของที่เจ้าของเปิดดูเมื่ออยากตรวจ
ไม่ใช่ของที่ต้องอ่านผ่านก่อนถึงจะรู้ว่าเราแนะนำอะไร

⏱️ **เวลาของเจ้าของคือทรัพยากรที่แพงที่สุดในโปรเจกต์นี้** —
แพงกว่า token · แพงกว่ารอบ CI · แพงกว่าความสมบูรณ์ของรายงาน

## DMAIC ต่างจาก PDCA ในโปรเจกต์นี้ยังไง

| | ใช้ตอนไหน | ไฟล์ |
|---|---|---|
| **DMAIC** | มีปัญหาเฉพาะจุดที่ต้อง**เลือกทางแก้** — บั๊ก · ตัวเลขตก · ผลไม่เป็นไปตามคาด | `src/lib/dmaic.ts` |
| **PDCA (การเติบโต)** | วงจรต่อเนื่องของการตลาด — ปล่อย → วัด → เรียน → ทำต่อ | `src/lib/growthPdca.ts` |
| **PDCA (คุณภาพ/ISO)** | วงจรของระบบบริหาร | `src/lib/eqms.ts` |

⚠️ **ทั้งสามใช้เกณฑ์ตัวเลขชุดเดียวกัน** (`MIN_FOR_RATE = 100`) — ห้ามนิยามเกณฑ์ใหม่ซ้ำ
เกณฑ์ที่ไม่ตรงกันคือที่มาของข้อสรุปที่ขัดกันเองระหว่างแผง

## เช็กลิสต์ก่อนกดส่ง

- [ ] เป้าหมายเป็นตัวเลขและมีเส้นตาย ไม่ใช่ "ให้ดีขึ้น"
- [ ] มีค่าตั้งต้น หรือประกาศชัดว่าวัดไม่ได้เพราะอะไร
- [ ] สาเหตุราก 1 ข้อ ไม่ใช่ลิสต์ความเป็นไปได้
- [ ] ทางเลือก ≥ 3 รวม "ไม่ทำอะไรเลย"
- [ ] มีข้อที่แนะนำ + เหตุผลที่ไม่เลือกอันดับสอง
- [ ] ทางที่ติดกฎถูกรายงานว่าพักไว้เพราะอะไร
- [ ] มีกลไกกันไหลกลับ (เทสต์/ตัววัด/ด่าน)
- [ ] **บรรทัดแรกของคำตอบคือข้อเสนอ ไม่ใช่ที่มา**
