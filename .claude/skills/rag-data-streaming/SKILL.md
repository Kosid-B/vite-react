## 1. 🔴 เรามี RAG อยู่แล้ว — ห้ามสร้างตัวที่สอง

ก่อนเสนออะไร ต้องรู้ว่าของเดิมคืออะไร (ตรวจสดในโค้ด 20 พ.ย. 2569):

**`src/lib/knowledgeBase.ts`** (105 บรรทัด · pure/tested) = RAG ตัวจริงของโปรเจกต์
- `KNOWLEDGE[]` — chunk ที่ **curate มือ** หัวข้อ `iso9001` / `pdpa` / `tis` / `general`
- `retrieve(query, k=4, topic?)` — ค้นแบบ **keyword ถ่วงน้ำหนัก** (คำอังกฤษเทคนิคถ่วง ×2 เพราะแม่นกว่า)
  · ภาษาไทยตัดเป็น **n-gram 3–4 ตัวอักษร** (ไม่มีการตัดคำ) + stoplist 19 คำ
- `buildContext(chunks)` — ใส่หมายเลข `[1][2]` ให้ AI อ้างอิงได้
- `ragInstruction(q)` — บังคับ AI ว่า *"อ้างอิงเฉพาะ context เท่านั้น · ถ้าไม่พอให้บอกตรง ๆ · อย่าเดา"*

🟢 **สายนี้ถูกเรียกใช้จริง** (ตรวจแล้ว ไม่ใช่โค้ดตาย): `src/pages/Knowledge.tsx:39,59,60`
→ `retrieve` → `buildContext` → `ragInstruction` → `callAiAssist` (Edge Function `ai-assist`)

🔴 **เจตนาที่เขียนไว้ในไฟล์ ห้ามเผลอกลับทิศ** (บรรทัด 3–4):
> *"retrieval แบบ keyword (ฐานความรู้ bounded) — **ไม่ต้องมี pgvector/embeddings/secret ใหม่**
> Phase 4b (อนาคต): เพิ่ม pgvector + embeddings เพื่อรองรับเอกสารที่ผู้ใช้อัปโหลดเอง"*

⇒ การไม่ใช้เวกเตอร์ **เป็นการตัดสินใจ ไม่ใช่ความขาด** · เงื่อนไขปลดล็อกเขียนไว้แล้วคือ **ผู้ใช้อัปโหลดเอกสารเอง**

### 🪤 กับดักชื่อซ้ำ (เสียเวลาแน่ถ้าไม่รู้)
`Agent.knowledgeBase` (`src/types.ts:163` · ใช้ใน `AICompany.tsx:1808–1815`) = **ช่องข้อความอิสระของแผนก**
**ไม่ใช่** โมดูล `knowledgeBase.ts` และไม่มี retrieval อะไรเลย
⇒ ตรงกับกฎโปรเจกต์: *"ประวัติแชต/prompt/ไฟล์อัปโหลด ไม่ใช่จีโนม"* — ช่องข้อความอิสระก็ไม่ใช่ฐานความรู้

## 2. สี่ขั้นของคู่มือ ↔ เรามีอะไรแล้ว

| ขั้นในคู่มือ | คู่มือบอกให้ใช้ | ของเราวันนี้ | สถานะ |
|---|---|---|---|
| **① เพิ่มบริบทให้ข้อมูล** (Data Augmentation) | ตัวเชื่อมต่อ → Flink → embedding → vector store | `KNOWLEDGE[]` curate มือ · bounded | 🟢 มี (คนละวิธี) |
| **② ประมวลผลด้วยโมเดล** (Inference) | เติมบริบทเรียลไทม์ก่อนเรียก LLM | `buildContext` + `ai-assist` | 🟢 มี |
| **③ เวิร์กโฟลว์** (Workflows) | เอเจนต์ให้เหตุผล · แตกคำถามยาวเป็นคำถามย่อย · แคช | 🔴 **ไม่มี** — ถาม 1 ครั้ง ตอบ 1 ครั้ง | 🟡 ช่องว่างจริง |
| **④ ตรวจหลังสร้างคำตอบ** (Post-Processing) | consumer group แยกตรวจคำตอบเทียบกฎธุรกิจ | **มีตัวตรวจครบ แต่ไม่ได้ต่อกับทางออกของ AI** | 🔴 ช่องว่างที่แพงสุด |

### 🔴 ข้อ ④ คือข้อที่คู่มือเล่าตรงกับปัญหาที่เรามีอยู่จริง
เรามีตัวตรวจคำกล่าวอ้างพร้อมใช้อยู่แล้ว — `violatesBrand()` · `brandIssues()` · `checkVideoScript()` ·
`zeroIsNotProof()` · `stateSafely()` · `reviewCampaign()` — ทั้งหมด pure + มีเทสต์
**แต่** CLAUDE.md บันทึกไว้ว่า จาก **15 จุดที่ส่งคำสั่งเข้า AI มีเพียง 1 จุด** ที่ได้รับบล็อกรัฐธรรมนูญ
และ `CeoAiAgent` / `ai-assist` / `ai-plan` / `agent-run` **ไม่ได้รับเลย** (กลไกเฝ้า: `constitutionReach.test.ts`)

⇒ คู่มือเรียกชั้นนี้ว่า "ขั้นที่ป้องกัน hallucination" · ของเราคือ **ตัวตรวจที่ยืนอยู่ข้างทาง ไม่ได้ขวางทาง**
⇒ **นี่คืองานที่ให้ผลมากที่สุดจากเอกสารฉบับนี้ และไม่ต้องซื้ออะไรเลย**

## 3. คัด 3 กอง (บังคับตาม skill `case-study-stage-fit`)

เฟสจริงของเรา: **`reach`** — ผู้เข้าชมหลักสิบ/สัปดาห์ · **ลูกค้าจ่ายจริง 0 ราย**
(อ่านสดจาก `stageFit.stageOf()` ก่อนใช้ตารางนี้เสมอ — **เฟสเปลี่ยน = ตารางนี้เปลี่ยน**)

### ✅ ทำได้ตอนนี้ (ฟรี · ไม่แตะ schema · ไม่แตะผู้ขาย)
1. **ต่อตัวตรวจคำตอบเข้ากับทางออกของ AI** (ข้อ ④ ข้างบน) — ของมีอยู่แล้ว แค่ยังไม่ได้ต่อ
2. **ใช้กฎ "เมื่อไรไม่ควรทำเวกเตอร์"** เป็นเช็กลิสต์ก่อนเติม chunk ใหม่ (ข้อ 4)
3. **แตกคำถามยาวเป็นคำถามย่อย** ใน `ragInstruction` — คู่มือระบุว่า LLM ให้ผลดีกว่าเมื่อคำถามสั้นลง (ยังเป็น 🟡 ไม่ได้ทดลองเอง)
4. **ขยาย `KNOWLEDGE[]`** — ต้นทุนเท่ากับเวลาเขียน · ยิ่งฐานความรู้กว้าง ยิ่งต้องมีข้อ 5
5. 🔴 **ใส่เกณฑ์คะแนนขั้นต่ำให้ `retrieve()`** — จุดบอดที่วัดเจอแล้ว (ข้อ 1.1)

### 🔴 1.1 จุดบอดของ retrieval ที่วัดเจอ 20 พ.ย. 2569 (ยังไม่แก้)

วัดสดด้วยคำถามจริง:

| คำถาม | `retrieve()` คืน |
|---|---|
| `"zzzqqq"` · `"xyz123"` · `"ราคาก๋วยเตี๋ยว"` | `[]` 🟢 **ซื่อสัตย์** |
| `"zzzqqq ไม่มีคำนี้ในฐานความรู้"` | `pdpa-security` · `iso-5` · `pdpa-consent` · `iso-7` 🔴 **ไม่เกี่ยวข้องเลย** |
| `"ความรู้"` | `iso-5` · `pdpa-consent` · `pdpa-security` · `iso-9` 🔴 |

**สาเหตุราก (1 ข้อ)**: ตัวกรองเดียวคือ `score > 0` และภาษาไทยเป็น n-gram 3–4 ตัวอักษร
⇒ **แชร์กัน 3 ตัวอักษรก็นับว่า "เกี่ยวข้อง"** · คำทั่วไปในประโยคไทยจึงลาก chunk ที่ไม่เกี่ยวเข้ามาได้เสมอ

🔴 **ทำไมเรื่องนี้ร้ายแรง**: `ragInstruction` สั่ง AI ว่า *"อ้างอิงเฉพาะ context · ถ้าไม่พอให้บอกตรง ๆ"*
แต่เราส่ง **ข้อความ ISO/PDPA ที่ดูน่าเชื่อถือ** ไปให้ทั้งที่ไม่ตอบคำถาม ⇒ AI ไม่มีทางรู้ว่าบริบทไม่เกี่ยว
**นี่คือช่องทาง hallucination ที่เกิดจากฝั่งเรา ไม่ใช่ฝั่งโมเดล** — ตรงกับขั้น ④ ของคู่มือเป๊ะ

⚠️ **ยังไม่แก้โดยตั้งใจ** — เป็นการเปลี่ยนพฤติกรรม retrieval ต้องเลือกวิธีก่อน (เกณฑ์คะแนนขั้นต่ำ ·
ต้องมี token ที่ยาวพอ · หรือบังคับให้มีคำอังกฤษ/ชื่อข้อกำหนดตรงกัน) ⇒ ของานตัดสินใจจากเจ้าของ

### ⏳ ยังไม่ถึงเวลา — **ต้องมีตัวเลขปลดล็อก ห้ามเขียน "เมื่อโตกว่านี้"**
| สิ่งที่รอ | ปลดล็อกเมื่อ | เหตุผล |
|---|---|---|
| pgvector / vector store | **ผู้ใช้อัปโหลดเอกสารเองได้** (เงื่อนไขที่ `knowledgeBase.ts` เขียนไว้เอง = Phase 4b) | ฐานความรู้ที่ curate แล้วมีขอบเขตจำกัด keyword พอ |
| แคชคำตอบ LLM | เมื่อ **คำถามซ้ำ** วัดได้จริง | ยังไม่มีปริมาณคำถามให้ซ้ำ · แคชที่ไม่เคย hit = ความซับซ้อนฟรี |
| เอเจนต์ให้เหตุผลหลายขั้น | หลังข้อ ④ ปิด | เพิ่มขั้นเรียก LLM ก่อนมีด่านตรวจ = เพิ่มพื้นที่ให้ hallucination |

### 🚫 ห้ามลอก (ต้องบอกว่าทำไม)
- **Confluent Cloud + Kafka + Flink** — คู่มือเองบอกว่าแก้ปัญหา *"ไซโลข้อมูล · ETL แบตช์ · หลายทีมดูแลคนละส่วน"*
  เราไม่มีปัญหาข้อไหนเลย: มี Supabase ตัวเดียว + Worker ตัวเดียว + ทีมคนเดียว ⇒ แก้ปัญหาที่เราไม่มี
- **Flink AI Model Inference / `ML_PREDICT`** — ผูกกับ Confluent Cloud · ของเราเรียก Claude จาก Edge Function อยู่แล้ว
- **สมัคร Confluent Cloud เอาเครดิตฟรี $400** (ข้อ 9 ของคู่มือ) — เครดิตฟรีไม่ใช่เหตุผลทางธุรกิจ
  และ **ของฟรีที่ต้องเขียนสถาปัตยกรรมใหม่รองรับ คือค่าใช้จ่ายที่แพงที่สุด**
- **อ้าง Notion / GEP Worldwide เป็นหลักฐาน** — เป็นเรื่องเล่าลูกค้าในเอกสารการตลาดของผู้ขาย
  🔴 และตรงกับ `videoBrief.PROOF.banned` ของเรา: ห้ามใช้เคสความสำเร็จของคนอื่นมาหนุนข้อเสนอของเรา

## 4. 🟢 กฎที่ใช้ได้ฟรีวันนี้ — "เมื่อไรไม่ควรทำเวกเตอร์"

กฎนี้เป็นกลางต่อผู้ขายและใช้ได้ทันที (คู่มือหน้า 9):

**ควรทำเวกเตอร์** · ไฟล์ไม่มีโครงสร้าง · ไฟล์ผสม (บทความวิจัยที่มีตาราง) · ข้อมูลมีโครงสร้างที่บางฟิลด์เป็นข้อความอิสระ (CSV ที่มีรีวิวลูกค้า)

**ไม่ควรทำเวกเตอร์** · ข้อมูลที่มีแต่ตัวระบุ (CSV รหัสสินค้า) · ค่าสรุปเชิงวิเคราะห์ (ร้อยละคนคลิกแบนเนอร์ — ควรสืบค้นจากฐานข้อมูลเชิงสัมพันธ์)
🔴 **และข้อมูลที่ขาดความหมายเมื่อแยกจากสคีมา เช่น เลขบัตรเครดิต เลขประกันสังคม — ห้ามทำเวกเตอร์เด็ดขาด**

⇒ เข้ากับกฎที่เรามีอยู่แล้วและต้องไม่ถอย: `quickcheck_submissions` **ไม่เก็บชื่อสินค้าที่ผู้ใช้พิมพ์**
(free text อาจมีชื่อร้าน/เบอร์) · `client_errors` **ไม่เก็บ IP/user id** ⇒ ของพวกนี้ห้ามไหลเข้าฐานความรู้ AI
