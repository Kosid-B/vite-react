# MOAT Architecture — ตรวจก่อนสร้างของใหม่

> แหล่งความจริง (โค้ดที่มีเทสต์ ไม่ใช่เอกสาร):
> `src/lib/competitiveStrategy.ts` · `src/lib/positioningEngine.ts` ·
> `src/lib/businessGenome.ts` · `src/lib/competitorMemory.ts`
> สถาปัตยกรรมเต็ม: `docs/product/MOAT-ARCHITECTURE-V1.md`

## 0️⃣ Golden Question — ถามก่อนทุกอย่าง

> **"สิ่งที่กำลังทำนี้ช่วยให้ธุรกิจเข้าใกล้ลูกค้า หลักฐาน กำไร หรือ Scale มากขึ้นอย่างไร?"**

ตอบไม่ได้ = ไม่สร้าง แม้ AI จะทำได้ · ⚠️ "เพราะระบบเรามีฟีเจอร์นี้อยู่แล้ว" **ไม่ใช่คำตอบ**
รัฐธรรมนูญเต็ม: [`AGENTS.md`](../../../AGENTS.md) · โค้ด: `founderConstitution.ts` · `founderMindset.ts`

## 0️⃣.5 คำถามที่สองก่อนเริ่ม

> **ฟีเจอร์นี้เพิ่ม moat หรือเพิ่มแค่จำนวนฟีเจอร์?**

ตอบว่า "เพิ่ม moat" ได้ก็ต่อเมื่อมันทำอย่างน้อย 1 ข้อ:

1. ทำให้ **Business Genome สมบูรณ์ขึ้น** (เก็บข้อมูลมีโครงสร้างเพิ่ม)
2. ทำให้ **กฎการตัดสินใจแม่นขึ้น** (Thai Business Playbook)
3. ทำให้ **ผลลัพธ์ไหลกลับเข้าระบบ** (Evidence → Learning → Genome)

ถ้าไม่เข้าข้อไหนเลย ⇒ มันคือ **POP** · สร้างได้ แต่ห้ามนับเป็นความได้เปรียบ

## 1️⃣ ไล่ 3 ชั้นเสมอ

```
POP  = ความสามารถ AI            (ต้องมี · ชนะไม่ได้)
POD  = วิธีสร้างธุรกิจ            (เหตุผลที่ต้องเลือกเรา)
VRIO = ระบบเรียนรู้ธุรกิจที่สะสมเอง  (สิ่งที่ลอกไม่ได้)
```

⚠️ **"มี AI / AI Agent / สร้างคอนเทนต์ได้" = POP** — AIS×Microsoft แจก AI Agent ให้ SME แล้ว

## 2️⃣ ก่อนพูดว่าอะไร "แตกต่าง" — ต้องผ่านด่านนี้

```ts
assessDifferentiation(claim, KNOWN_MARKET, copyDifficulty, evidence)
```

| ผล | แปลว่า |
|---|---|
| `pop` | ตลาดพูดกันหมดแล้ว — หาข้ออื่น |
| `weak-pod` | ไม่มีใครพูด แต่ลอกง่าย — ทำให้ต้องพึ่งข้อมูลของเรา |
| `hypothesis-pod` | ลอกยาก แต่ไม่มีหลักฐาน — เก็บหลักฐานก่อน |
| `strategic-pod` | ใช้เป็นข้ออ้างหลักได้ |

## 3️⃣ ก่อนออกแคมเปญ/คอนเทนต์ — ต้องผ่าน 10 คำถาม

```ts
reviewCampaign(brief)   // pass:false = สร้างไม่ได้ ไม่ใช่แค่เตือน
```

4 กฎบังคับ: **NO POD** · **NO EVIDENCE** · **LOW SAMPLE** · **POP ONLY**
DNA ห้ามสลับ: `Customer Problem → Business Insight → POD → Proof → AI-enabled Action → Experiment → Measurement → Learning`

🔴 **AI ต้องอยู่กลางสาย ในฐานะกลไก ไม่ใช่หัวเรื่อง**

## 4️⃣ ก่อนสร้าง — เช็กว่าปลดล็อกหรือยัง

```ts
moatReadiness(activeUsers)   // ผู้ใช้ภายนอกที่ใช้จริง (วันนี้ = 0)
```

| ต้องมีผู้ใช้ | สิ่งที่ปลดล็อก |
|---|---|
| **0** | Business Genome · Thai Business Playbook |
| **1** | Experiment Memory |
| **5** | Decision Engine (ที่เรียนรู้จากผลจริง) |
| **30** | Benchmark Network · Learning Loop |

⚠️ **กฎ ≠ เอนจิน** — เขียน decision rules ได้ตั้งแต่วันนี้ แต่เอนจินที่เก่งขึ้นจากผลจริงต้องรอผู้ใช้

## 5️⃣ 🔒 เส้นที่ห้ามข้าม

- **ห้ามแตะ schema/migration** จนกว่า `schemaChangeAllowed()` ใน `src/lib/releaseGates.ts` จะคืน `allowed: true`
  ห่วงโซ่: `Gate B` → `Phase 1 Acceptance #2` → `Freeze Phase 1 baseline` → Strategy Layer
  (⚠️ สถานะสดอยู่ในไฟล์นั้นที่เดียว — ห้ามอ่านสถานะจากเอกสาร/สคิลล์ · `unknown` กั้นเท่ากับ `open`)
- **ห้ามประกาศว่ามี moat ที่ยั่งยืน** — วันนี้ 4 บัญชี · จ่ายเงินจริง 0 ราย
- **ห้ามเอา North Star ขึ้นเป็นพาดหัว** — ไม่มีใครค้นหาชื่อหมวดหมู่ · พาดหัว = ปัญหา
- **ประวัติแชต/prompt ไม่ใช่จีโนม** — ลอกได้ทันทีที่เปลี่ยน LLM
