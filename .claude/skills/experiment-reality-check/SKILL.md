# Experiment Reality Check — ตรวจความจริงก่อนเชื่อผล

> เกิดจากเคสจริง 16 ส.ค. 2569: หน้า Landing มี A/B ค้าง 3 ชุด
> ตัวเลขจริงคือ **ผู้เข้าชม 60 คน · เลื่อนเกินครึ่งหน้า 1 คน · กด CTA 4 คน · สมัคร 1 คน**
> 2 ใน 3 ชุดทดสอบของที่อยู่ใต้ครึ่งหน้า → **59 จาก 60 คนไม่เคยเห็นความต่างเลย**

## กฎข้อที่ 1 — นับ "คนที่เห็นจริง" ไม่ใช่ "ผู้เข้าชมทั้งหมด"

เลขผู้เข้าชมหลอกตาที่สุด เพราะมันใหญ่และดูเหมือนพอ

```
ของเหนือครึ่งหน้า  → คนเห็นจริง = ผู้เข้าชมทั้งหมด
ของใต้ครึ่งหน้า    → คนเห็นจริง = คนที่เลื่อนถึง         ← มักน้อยกว่าสิบเท่า
ของหลัง login     → คนเห็นจริง = คนที่ล็อกอินและเปิดหน้านั้น
ของในอีเมล        → คนเห็นจริง = คนที่เปิดอีเมล
```

**ถามเสมอ: "กี่คนมีโอกาสเห็นความต่างนี้จริง ๆ"** ไม่ใช่ "มีคนเข้าเว็บกี่คน"

ในโค้ดนี้: `reachableAudience(agg, placement)` ใน `src/lib/experimentPlan.ts`

## กฎข้อที่ 2 — ตัวชี้วัดต้องเกิดบ่อยพอจะวัดได้

วัดที่ "สมัคร" ตอนมีคนสมัคร 1 คน = วัดความบังเอิญ ไม่ใช่วัดผล

| เหตุการณ์ | เกิดบ่อยแค่ไหน | ใช้วัดได้ไหมตอนคนน้อย |
|---|---|---|
| เปิดหน้า | ทุกคน | ✅ แต่บอกอะไรไม่ค่อยได้ |
| เลื่อน / หยุดอ่านส่วนนั้น | บ่อย | ✅ ดีที่สุดตอนเริ่มต้น |
| กดปุ่มหลัก | ปานกลาง | ✅ ใช้เป็นตัวหลักได้ |
| สมัคร | น้อยมาก | ❌ ต้องรอจนมีหลักร้อยครั้ง |
| จ่ายเงิน | น้อยที่สุด | ❌ |

**เลือกเหตุการณ์ที่อยู่ก่อนหน้าในเส้นทางเดียวกัน แล้วบอกให้ชัดว่าเลือกเพราะอะไร**

## กฎข้อที่ 3 — คนน้อย ให้รันทีละชุด

รันพร้อมกันหลายชุดไม่ผิดตอนคนเยอะ (ความต่างเฉลี่ยออกกันเอง)
แต่ตอนคนหลักสิบ มันแปลว่า **อ่านไม่ออกสักชุด** และเสียเวลาไปทั้งหมด

## กฎข้อที่ 4 — "หยุด" ไม่เท่ากับ "ฟีเจอร์นี้แย่"

หยุดเพราะ *ยังพิสูจน์ไม่ได้* — จึงต้อง:

- [ ] เลือกค่าตั้งต้นด้วย **เหตุผล** (หลักการโปรเจกต์ / กลุ่มเป้าหมายรอบนี้)
- [ ] **เขียนเหตุผลไว้ในโค้ด** ไม่ใช่จำเอง
- [ ] มีเงื่อนไขว่าจะกลับมาทดลองอีกเมื่อไหร่

⚠️ ห้ามหยุดแบบลบทิ้งเงียบ ๆ — คนอ่านทีหลังจะนึกว่าไม่เคยคิดเรื่องนี้

## กฎข้อที่ 5 — แยก "ปรับตามสถานะ" ออกจาก "การทดลอง"

| | ทดลอง (A/B) | ปรับตามสถานะ (Dynamic PLG) |
|---|---|---|
| ใครได้เห็น | สุ่มแบ่ง | ทุกคนที่อยู่ในสถานะนั้น |
| เทียบกับใครได้ | อีกกลุ่มที่สุ่มมาเหมือนกัน | **เทียบไม่ได้ — ไม่ได้สุ่มมา** |
| ต้องรอคนเยอะไหม | ต้อง | ไม่ต้อง ทำได้เลย |

ตัวอย่าง: "คนที่เคยกรอกฟอร์มแล้วกลับมา เห็นตัวเลขของตัวเอง"
= ปรับตามสถานะ ไม่ใช่ A/B — เพราะกลุ่มนี้ต่างจากคนทั่วไปตั้งแต่ต้นอยู่แล้ว
**อย่าเอาไปทำเป็น arm แล้วสรุปว่ามันช่วย conversion**

## กฎข้อที่ 6 — แผนต้องอยู่ในโค้ด ไม่ใช่ในเอกสาร

เขียนว่า "หยุดชุดนี้แล้ว" แต่โค้ดยังสุ่มต่อ = ไม่มีอะไรเปลี่ยน
ต้องมีเทสต์บังคับว่าหน้าเว็บ **เรียกใช้แผนจริง**

```ts
expect(page).toContain("frozenVariantOf('layout')")   // ไม่ใช่แค่มีแผนไว้เฉย ๆ
```

## เช็กลิสต์ก่อนรัน/อ่านผลการทดลอง

- [ ] คนที่ **เห็นความต่างจริง** มีกี่คน (ไม่ใช่ผู้เข้าชมทั้งหมด)
- [ ] ต่อกลุ่มถึง 30 คนหรือยัง
- [ ] ตัวชี้วัดที่ใช้ เกิดขึ้นกี่ครั้งแล้ว (ต่ำกว่า ~30 ครั้ง = ยังเทียบไม่ได้)
- [ ] ตอนนี้รันอยู่กี่ชุดพร้อมกัน
- [ ] ถ้าจะหยุด — เลือกค่าตั้งต้นเพราะอะไร เขียนไว้หรือยัง
- [ ] สิ่งนี้เป็นการทดลอง หรือการปรับตามสถานะ
- [ ] โค้ดเคารพแผนจริงไหม มีเทสต์ยืนยันไหม

## ประโยคที่ต้องกล้าพูด

- ✅ "ชุดนี้วัดไม่ได้ เพราะคนเห็นจริง 1 คน — หยุดดีกว่ารอ"
- ✅ "ยังสรุปไม่ได้ ต้องมี CTA อีกประมาณ 26 ครั้ง"

- ❌ "เก็บข้อมูลไปเรื่อย ๆ ก่อน เดี๋ยวก็รู้" (ถ้าคนไม่เห็น รออีกปีก็ไม่รู้)
